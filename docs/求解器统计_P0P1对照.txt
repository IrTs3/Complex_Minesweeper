──────────────────────────────────────────────────────────────────────────
P1 为什么有效：宽度 vs 变量数
──────────────────────────────────────────────────────────────────────────
枚举的复杂度是 O(D^n)（n = 分量变量数，33~64）；
DP 的复杂度是 O(D^w)（w = 因子图的**诱导宽度**）。
实测 Medium 的分量：

    17-32 变量：诱导宽度 中位 4 / p90 6 / 最大 6
    33-64 变量：诱导宽度 中位 5 / p90 6 / 最大 6

D=5 → 5^6 = 15625。相对 5^40 差了几十个数量级。这就是为什么 DP 能把降级从
1264 压到 10。

──────────────────────────────────────────────────────────────────────────
DP 的正确性怎么保证
──────────────────────────────────────────────────────────────────────────
oracle 对拍（/tmp/dpcheck，用 MS_FORCE_DP 强制每个分量都走 DP）：
  独立暴力枚举 5^N 重算 anyMine / anySafe / 雷型 / 含雷率，逐项比对。
  最后一版：221 个 DP 分量、20669 个暴力解、最大 N=9 → **0 不一致**。
DP 与 DFS 的唯一语义差异：DP 不做 `re<=rlim && im<=ilim` 剪枝（DFS 会做）。
少剪枝 = 解集是超集 = 见证更保守，不会错下结论；oracle 也是按「不加 cut」比的。

──────────────────────────────────────────────────────────────────────────
Hard 只有 14%：原假设被实测否定（2026-10-24 P2）
──────────────────────────────────────────────────────────────────────────
【原来的假设】DP 分量没有 (re,im) profile → 它被整批并进吸收池 →
吸收池变大 → valid 的判据 `x + y - best <= absorb` 变松 → 全盘雷数约束失效。

【实测结果：假设错了，错在数量级】
  Hard 100 局、4382 次 analyze：
    absorb     avg = 193.0   max = 369
      其中 interior（不接触任何线索的内部格）  avg = 191.4  max = 369
      DP 分量贡献                            avg =   1.6
    Rtot+Itot  avg =  48.8   (R 24.7 / I 24.1)
    前沿格     avg =  37.6   max = 100
    判据真正有约束力（absorb < Rtot+Itot）的次数 = 109 / 4382 = 2.5%，平均余量 -144

  → 吸收池的 99% 是内部格，跟 DP 分量几乎无关。x+y-best 最大不过 48，
    而 absorb 是 193，所以判据在 97.5% 的场面恒真 —— 这是结构性的，
    把 DP 分量挪出去、或给它造一份 profile 都改变不了。
  → 顺带排除了另一个怀疑：globalFilter 3910 次调用 100% 成功、
    prefMax 仅 366（上限 8000）；exactProbs 1620 次调用 100% 成功；
    analyze 全部走全局路径（全局 3910 / 局部 0）。不存在"全局路径没跑起来"的问题。

【为验证假设而实现的三处改动，全部零收益，都保留但默认关闭】
  1) BucketDP::computeSupport —— bool 半环前向，用 Minkowski 和算出分量级
     (实雷数, 虚雷数) 可达集合，接进 globalFilter 的 pref/suff/valid。
     结果：Hard 14.0% → 14.0%，Medium 65.0% → 66.0%（噪声内）。
     开关 kEnableDpSupport = false。
  2) BUDGET 状态的见证接进 pmF/psF（覆盖搜索的「预算内穷尽且未找到」是
     可靠证明；COVERED 只有随机采样，仍必须当未知）。
     结果：14.0% → 14.0%。原因是 exhausted 只占 1.2%，而 found 占 61%
     意味着"两个取值都可行"= 仍然未知。这是正确性修复，保留。
  3) 猜格 tie-break（内部格按到最近已开格的曼哈顿距离近者优先）。
     结果：14.0% → 13.0%。开关 kEnableTieBreak = false。

【唯一有实际效果的一处】
  DP 失败后不再重跑一次 ——— BucketDP::run 是纯函数（同 CompTask /
  maxWidth / workCap 必然同结果），而失败点常是"跑到 workCap 才放弃"，
  重试等于把这份开销付两遍。nv ≥ 64 的长尾局里这是白烧的一整轮。

那么 Hard 14% 到底是什么性质？—— 关键诊断
──────────────────────────────────────────────────────────────────────────
用 gDbg 路径直接读 mine 做**无偏校准**（不用"是否爆"，那有生存者偏差：
踩雷即 break，能到达高 P 桶的局本来就运气好）：

  预测 P 桶     次数   真实含雷   真实率    预测中值
  <0.02         330      0        0.0%       1.0%
  0.02-0.05      84      0        0.0%       3.5%
  0.05-0.10      46      2        4.3%       7.5%
  0.10-0.20      91     13       14.3%      15.0%
  0.20-0.35      87     17       19.5%      27.0%
  ── 其中内部格（用 pIn 的）──
  0.10-0.20      54     10       18.5%      15.0%
  0.20-0.35      84     17       20.2%      27.0%

  → 概率是**准的**，且整体偏保守。不存在"P 被系统性低估"这回事。

【Hard 的真实画像（60 局）】
  * 猜 14.4 次/局；猜爆 52/60；卡死 = 0（所有负局都是猜爆，不是标不上雷）
  * 陷阱猜（P>=0.2）占 13.6%；P>=0.3 只有 1 次
  * 降级分量只剩 14 个 / 100 局（DP 已精确解出 1177 个分量）
    → 推理层已经很强，瓶颈不在"算不完"，而在"这局本来就要猜这么多次"
  * 胜率 ≈ ∏(1-P_i)。min-P 贪心已经接近它自己的饱和点。

【结论】要再往上，只能改「选哪一格」的策略本身，而不是把概率算得更准、
也不是把更多分量算出来。剩下的有依据的方向只有一个：
  one-step lookahead —— 对 P 最小的 top-K 候选，假设它安全、在棋盘副本上开格、
  重新 analyze，比较"猜中之后新局面的最小 P / 还需再猜几次"。
  代价 K 倍 analyze（Hard 现在最坏 21-22s，30s 预算下 K=2~3 可行）；
  文献里这类改动通常 ±2~5 点且**可能为负**，必须 500 局 A/B。
  （P3 又排除了另外两条：盘末按轴收口、DP 边际扣减吸收池 —— 见下节。）

【A：盘末按轴收口（gauge 一致兜底标雷）】
  猜想：盘末未开的格其实全是已知的雷，但 mustMine_ 要求雷型在全部相容解里唯一，
        同轴 ± 未锚定时会被排除 → 标不上 → 只能去开 → 必爆。
  实现：猜之前扫「未开格数 == 剩余雷数」的场面，按分量挑一个合法全局取向，
        把整片未开格当雷标上，直接判胜。
  实测（seed=20261008，Medium 100 局 / Hard 60 局）：
        触发条件成立（未开格数 == 剩余雷数）          0 次 / 0 次
        因此判胜的局 / 标下的格                        0 / 0
        猜格中被证实是雷却「必雷但型不唯一」的格        0 次 / 0 次
        每次猜时「必雷但型不唯一」格累计                866 / 1861
  第三行说明这类格确实存在，但求解器从不落到「必须开它们」的局面。
  是恒等式而非运气，原因三条：
    ① 求解器先标必雷，标够了 Board::won() 立刻成立并结束，不会拖到「只剩雷」；
    ② Board 判胜口径里，± 型不唯一本身就是**整分量翻转**的自由度（未锚定时合法），
       所以「型不唯一」的必雷格根本不需要额外处理；
    ③ 必安格总进 forcedSafe_ 被开掉，盘面不会停在「未开格全是雷」。
  → 代码全删（约 50 处：planFinishByFlags、finCand / finRejCross / finRejUnk /
    finRejSign、guessCertain / pendingMineCells、typeMaskGrid_ / proofMine_ /
    proofSafe_），只在原实现位置留注释说明，防止以后再想起来。

【B：DP 分量与全局耦合（从吸收池扣掉 DP 边际）】
  猜想：DP 分量没有 profile、被整批并进吸收池，稀释了内部格概率 pIn
        → 从吸收池总额里扣掉 DP 分量的 ΣcellProb，得到「纯内部格」口径的 pIn。
  实测（配对同棋盘，seed=20261008，budgetK=1）：

               胜率            陷阱猜 P>=0.2    降级分量
    Medium 500  65.8% → 62.6%      190 → 81        7 → 10
    Hard   150  13.3% → 10.7%      336 → 29       39 → 39

    配对（Medium 500 局）：基线赢而 B 输 23 局，B 赢而基线输 7 局
    → Δ = -16 胜，McNemar 精确检验 p ≈ 0.006，不是噪声。
    （陷阱猜计数下降不是改善：内部格 P 被压扁后，trap 分类本身失去意义。）
    注：这里的 13.3% 是 seed=20261008、Hard 150 局的**配对样本**，不是新基线；
        权威基线仍是 seed=20261024 的 500 局 17.4%（见 求解器统计_大样本定稿.txt），
        两者差 1.3σ，属样本量差异。

  为什么必然为负，两条都量了：
    ① DP 不剪 rlim/ilim → DP 解集是超集 → ΣcellProb **不是**期望雷数。
       Hard 40 局、1080 个 DP 分量：ΣcellProb = 24387.3 vs 真实雷数 10906，
       即 **2.24×**。拿 2.24 倍的数去扣总额，等于凭空蒸发雷数。
    ② 池子本来就没被稀释：吸收池 avg 203.8 格/次，其中 interior（不接触任何线索）
       占 184.9，DP 分量只占 ~19。扣完之后内部格概率整体塌进 <2% 桶，
       而该桶真值含雷率 22.8% —— 「低风险」提示变成骗人的，猜格被引到 P 虚低的死路。
  → 代码逐字回退，与基线**逐位一致**（Medium 100 局行：66.0 / 632 / 255 / 40 / 0 / 5）。
    结论写进 SolverEngine.h 的 ensureExactProbs 上方注释。
  顺带确认的真缺陷：DP 前沿的边际概率确实被高估 2.24×（影响跨分量排序与 UI 提示），
    但**不能用边际去修**，只能让 DP 输出「按雷数分层的历史权重」——P1 级改造，未做。

【本轮新增的两个观测口径（tools/solver.cpp，长期保留）】
  1) 理论存活上界 = exp(Σlog(1-P) / 猜局数)（几何均值）。
       Hard 150 局 27.3% / Medium 500 局 61.2%，对照实测 13.3% / 65.8%。
       ⚠ 它**系统性偏高**：早死的局只乘了少数几个 (1-P)，越早死贡献越大。
       只用来查「算得离谱」（若实测反而高于上界，说明概率算错），
       不要拿 27.3% 当「还有 14 点可提」的证据。
  2) 6 档猜格概率校准表（<2% / 2-5% / 5-10% / 10-20% / 20-35% / >=35%），
     --dbg 时另给内部格子列与真值。实测：
       Hard 150：10-20% 桶实际 13.2%、20-35% 桶实际 18.4%
       Medium 500：同两桶 13.9% / 20.7%
     → 再次确认校准偏保守，「把概率算得更准」不是提胜率的路。

【P3 之后剩余方向】

已知取舍
──────────────────────────────────────────────────────────────────────────
* DP 分量不带 profile → 全盘概率仍标 approx（诚实：不虚报精度）。
* DP 不做雷数上限剪枝（见上），只影响保守程度，不影响安全。
* kDpMaxWidth=8 / kDpWorkCap=8e6：超限就退回采样覆盖（实测极少触发）。
* 子集相减（deriveSubsetCons）仍默认关闭：P0 实测负收益，留给未来的 DP 复用。
