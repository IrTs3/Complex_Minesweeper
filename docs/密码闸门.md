没通过验证的人**什么都看不到**——

两个入口是**同一个 nginx server 块**，闸门语义一字不差（详见下文「域名接入」一节）。

## ⚠️ 先说清楚：这**不是**安全边界

**域名侧的明文已经在 2026-10-20 收口**：80 除 ACME 续期挑战外一律 302 到 https，
会话 cookie 在 https 上带 `Secure`，`IP:8080` 那个内测入口收回服务器内部（只绑 `127.0.0.1`）。
所以现在**不存在「同网络抓包就能拿到密码」的对外通道**了。

但强度仍然是 **"防误入 / 软隔离"**，拦得住随手点进来的人、搜索引擎和扫描器，  
拦不住下面这些：

- **入口 token 走的是 URL**：会进 nginx 访问日志、浏览器历史、以及被 Referer 侧留存的场合。
  拿到网址的人就等于拿到门牌 —— 它不是第二道认证，是唯一的入口凭据。
- **共享口令**：密码表里是"给谁的哪条密码"，不是个人身份；一条密码泄露 = 拿到的人全都能进。
- **HSTS 锁不住第一次**（2026-10-21 点头才加的，`max-age=15552000` 即 180 天，见「HTTPS」一节）：
  浏览器要先见过一次 https 才会记住这条。所以从没访问过 `https://ty0712.com` 的人手输域名时，
  仍然先走一次明文 80 再被 302 上来，中间那跳是明文的（虽然 80 上除了挑战文件什么都取不到）。

缓解手段：

1. 会话有 24 小时绝对上限（`cmsgate.service` 里的 `--session-ttl 86400`），不是永久有效。
2. 怀疑泄露就 `passwd` 轮换或 `rm` 删掉那个密码，**下一次请求立即失效**。
3. 怀疑入口泄露就 `cms gate-path rotate`，访客手里的网址当场全线 404。

## 架构

```
访客 ──https:443──> nginx ──auth_request──> authd.py（仅 127.0.0.1:8090）
      （明文 80 只回一条 302；127.0.0.1:8080 是自己人用的回环口子）
                              │                        └── /var/lib/cmsgate/
                              │                              ├── secret.key      0600  签名密钥
                              ├─ 未登录：任何受保护 URL     ├── passwords.json  0600  哈希表（每条的启用/有效期）
                              │           → 404（当作不存在）├── gateconfig.json 0600  总开关 + 管理口令哈希
                              │                              ├── revoked.json    0600  已登出会话签名（重启后仍作废）
                              └─ 登录入口：/gate/<TOKEN>/    └── usage.jsonl 0600 访问记录
                                 （随机不可猜，见下一节）
```

**`gateconfig.json` 不存在时按「需要密码」处理（fail-closed）**——读不到配置宁可多要一次密码，
也绝不把整站敞开。它**只在服务器上保存**，本地不留副本（免得造成"删掉本地文件就能绕过"的假安全感）。

**公开（无需密码，指 443 与回环那个内容块）**：`/gate/<TOKEN>/**`（秘密登录入口，含它自己的 css/js）、  
`/assets/ibmplex-ascii.woff2`、`/assets/IBMPlexSerif-Regular.ttf`、`/learn/**`（学习站）、  
`/__login` + `/__logout`（POST-only、限流、不返回内容）、`/.well-known/acme-challenge/**`（续证书用，80 与 443 都有）。  
其余一律受保护 —— 包括 `/gate/` 本身和两张背景图 `bg.webp` / `bg.jpg`（2026-10-19 收进闸门）。  
**明文 80 是另一回事**：那里除挑战文件外只剩一条 302，`/gate/` 前缀直接 404（不让 token 上明文）。

**未登录为什么是 404，而不是密码页或裸 401**（2026-10-19 改）：密码页和 401 都等于  
告诉陌生人「这里有受保护的东西」；404 则和「服务器上根本没这个文件」完全同形。  
实现：所有受保护 location 统一挂 `error_page 401 403 502 504 =404 /__nf;`，  
`/__nf` 是 `internal` 的 404 汇点（外部直接请求它也是 404，不会变成新入口），  
头上仍带 `no-store` + CSP——错误响应若被缓存复用，一样能绕过 `auth_request`。

### 登录入口本身也 404 化：`/gate/<TOKEN>/`（2026-10-19）

404 模型上线后剩最后一个洞：`/gate/` 本身是公开的，任何人（和任何爬虫）都知道  
「这里有个密码门」。**但登录页不能要求先登录才能看**（`auth_request` 一旦挂上去就是死循环），
所以它只能保持「公开、但不告诉你存在」的形态 —— 把入口挪到随机不可猜的路径：

```
/gate/<TOKEN>/          ← 未登录：密码页；已登录：302 到 /game
/gate/                  ← 无会话者 404（和游戏页一样）
```

入口这一层同样看会话（2026-10-22 改）：`location = /gate/<TOKEN>/` 挂 `auth_request`，
已登录的人不再被要求再输一次密码，而是 `proxy_pass http://127.0.0.1:8090/entry`，
由 authd 验完 cookie 当场 302 到 `/game`；未登录时 `error_page 401 … =
/gate/<TOKEN>/index.html` 把密码页换上来。密码页与它的 css/js 放在同一个
`^~ /gate/<TOKEN>/` 前缀里、不走 `auth_request`——否则「要登录才能看登录页」是死循环。

| 事项 | 说明 |
| --- | --- |
| TOKEN 存在哪 | **只在服务器** `/etc/nginx/snippets/cms-gate-path.conf` 首行 `# gate-token: <TOKEN>`；不进 git、不进日志，**但自 2026-10-19 起随每日快照一起备份**（理由与恢复步骤见「数据备份」与 [`server/RESTORE.md`](../server/RESTORE.md)） |
| 谁生成 | 随机入口一律 `openssl rand -hex 12` / `secrets.token_hex(12)` = **24 个十六进制字符（96 bit）**。`deploy-web.sh` **每次按当前模板重渲染**这份片段，token **沿用**首行读出来的现有值 —— 只有片段不存在时才现生成，所以重部署绝不换掉大家收藏的入口，也不会让模板里新加的那行配置「因为文件早就存在」而不生效 |
| 长度口径（2026-10-21 裁决） | **随机**生成/轮换固定 24 位；**手动** `set` 仍允许 12~32 位且**不加熵警告**（`^[a-z0-9]{12,32}$` 管的是形状，不是强度 —— 短入口是留给人自己承担风险的口子，工具不替人判断）。改长度只影响下次生成，当前入口不动 |
| 怎么看 | `cms gate-path status`（只读、不问管理口令）或 cmsui 顶栏芯片 |
| 怎么换 | `cms gate-path set <token>` / `cms gate-path rotate`（要管理口令，走 `--admin-stdin`）；cmsui 芯片里同三件事。界面/脚本喂 token 用 `--token-stdin`：token 是唯一的登录凭据，而 argv 对同机任意进程可见（`ps aux`） |
| 复制给人 | cmsui 芯片里「复制完整网址」给的是**站点前缀 + 路径**整条（裸路径粘到微信/邮件里打不开）。前缀只有 cmsui 后端一份 `SITE_ORIGIN`（环境变量 `CMSGATE_SITE` 可覆盖，日后换域名/上 HTTPS 只改这一处）；CLI 的 `gate-path status` 刻意只回路径——整站对外地址不归那个工具管，免得长出第二份「站点地址」真相 |
| 形状校验 | `^[a-z0-9]{12,32}$`，写入前就地拒绝 —— 这个串会被拼进 nginx 的 `location` 行，`}`/换行/引号就是配置注入 |
| 换的方式 | 备份 `.bak` → 写 `.new` → `mv` → `nginx -t` → `systemctl reload nginx`，任一步失败原样回滚（与 `cms landing` 同构） |
| 换掉的后果 | 旧入口立即 404、所有人手里的登录网址失效 —— 得把新 URL 重新发给需要登录的人 |

nginx 侧必须用 `location ^~ /gate/<TOKEN>/`：只有 `^~` 能在最长前缀命中后终止匹配，
压过带 `auth_request` 的正则 `~* \.(js|css|…)$`——否则 `/gate/<TOKEN>/gate.css` 自己就 404，
登录页变成没样式的裸 HTML（这个坑在学习站上踩过一次，见下面「学习站」一节）。
配套：`web/gate/index.html` 引用 css/js 一律**相对路径**（`gate.css`），写成绝对 `/gate/gate.css`
在秘密入口下会打到已 404 的旧路径。

片段里补尾斜杠那一条用 **`return 302`，不是 301**：301 是永久跳转，会被浏览器**长期缓存**，
轮换 token 之后，存过旧地址（不带斜杠）的人会被缓存里那条 301 直接带进一个 404，
怎么刷新都回不来 —— 一个纯缓存问题能把唯一登录入口对老访客永久杀死。302 不缓存，换完就活。

⚠️ 要动这份片段就用 `cms gate-path set <token>`（哪怕 token 不换、原样 set 一次），**别手工 `sed`**：
本轮线上迁移 301→302 时，一条替换串结尾少写了一个 `/`，把跳转目标写成了 `/gate<token>/`
这种"形状合法但路径不存在"的串 —— 而 `nginx -t` 照样通过，语法检查抓不到语义错误。
生成器是整份重写，不存在这种局部改坏的中间态。

**背景图为什么也收进闸门**：`assets/bg.jpg` 之前作为密码页的 CSS 背景是公开的，而这张
《云上城堡》**没拿到商用授权** —— 匿名能 `curl` 走完整原图，等于未授权素材公网裸奔。
现在它落到带 `auth_request` 的正则块：匿名 404、登录后 200（会话 cookie 是 `Path=/`，
覆盖 `/assets/*`，所以游戏画布取图完全不受影响）。登录页自己改用 **CSS 渐变**背景
（`web/gate/gate.css`），不再依赖这张图 —— 它只给匿名访客看，本来就不该出现未授权素材。

设计上刻意保证的一件事：**密码页是零依赖的纯 HTML/CSS + 一个小 JS，不引用 `dist/*.js`**。  
否则那些文件必须对未登录者可见才能被加载，等于把游戏逻辑全部公开，闸门就白装了。

### 密码页的输入与反馈（2026-10-16 补）

| 元素 | 写法 | 为什么 |
| --- | --- | --- |
| 显示/隐藏 | `#reveal` 按钮切 `input.type` | 手机上输错一位看不见，只能整串重输 |
| CSS 选择器 | `#pw` 而**不是** `input[type="password"]` | 「显示」会把 type 切成 text，用属性选择器则一切换样式全丢 |
| 提交中 | 按钮文字变「验证中…」 | 只改 disabled 的话慢网络下界面毫无变化，用户会反复戳 |
| 节流提示 | 显示 `Retry-After` 的**具体秒数** | 只说「等一会儿」，用户会以为密码坏了并去问管理员 |
| 错误播报 | `role="alert"` **+ `aria-live="polite"`** | 读屏软件靠它播报「密码不正确」；⚠️ 这两个属性**都不许删** |

**XSS 面为零**：错误文案一律 `textContent` 写入，没有 `innerHTML`；  
**URL 参数已经完全不参与渲染** —— 旧的 `?e=N` 编号映射表（2026-10-19 删除）本来就只在
固定表里查、从不把参数原样写进 DOM，现在连这张表都不存在了；  
页面无内联脚本与 `on*` 事件属性（CSP `script-src 'self'` 也挡着）。

**无 JavaScript 时怎么看到拒绝原因**（2026-10-19 改）：
旧写法是服务端 `303` 跳回 `/gate/?e=N`，但 `/gate/` 现在对无会话者一律 404，
那条回跳落地就是一页 404 —— **访客只知道"坏了"，不知道"为什么坏了"**。
现在改成：表单仍走原生 `POST /__login`，由 **authd 自己把那一句原因写在响应的正文里**
（`401`/`429` + `text/html` + `Retry-After`，一个自包含的纯文字页面，读完用浏览器后退回登录页）。
这样服务端**不需要知道秘密入口在哪**，也就没有任何"把 token 广播出去"的通道。
⚠️ 那个内联页面**不许写 `<style>` / `style=` / 内联 `<script>`**：继承的 CSP 是
`style-src 'self'; script-src 'self'`，写了会被浏览器静默拦掉，只剩裸 HTML。

### 装饰星光与 USTC 弹字（2026-10-19 网页端 / 2026-10-20 双端 + 登录页）

`web/ts/fx.ts` 在 `#board` 上叠一层全屏 2D 画布 `#fx`：随机飘动的星光，以及  
左键/右键点击时在点击处弹出彩色的 `U S T C` 四个字母。**纯装饰，不进游戏逻辑**，  
学习站 `/learn/` 一个字都没碰。

2026-10-20 三处扩展：

- **弹字受复选框门控**：只有勾了「红专并进，理实交融」（`ustcMode`）才弹字母，星光不受影响。
  复选框切换时 `game.ts` 调 `updateFx({ ustcOn })` 实时推送，不需要刷新页面。
- **星光密度 / 半径倍率进 Settings**：两行滑块 `starDensity` **0..7.12 颗/100×100px（默认 2.17，两位小数，0.01 步进，0 = 彻底关闭）**、
  `starScale` 0.6..3.0（默认 1.7）。密度的单位就是「每 100×100 逻辑像素多少颗」，
  实际颗数 = 密度 × **当前视口 CSS 像素面积** ÷ 10000（`dpr` 与物理分辨率都不参与）。
  密度滑块下面直接显示 `2.17 颗/100×100px → 本窗口 ≈ N 颗（上限 M 颗）`（M 是密度 7.12 时本窗口的颗数），
  换难度/换窗口后 N 与 M 都会变 —— 密度值本身不变，变的是实际颗数。
  2026-10-22 之前密度的单位是「参考视口 1512×982 下的颗数」（0..800）；旧存档没有 `starUnit` 标记，
  两端读入时会先按 `值 × 10000 ÷ (1512×982)` 折成新单位再保留两位小数，老用户观感不变。
  窗口尺寸一变就**整池重铺**（只补/砍差额会把旧星全留在原区域，短时间看着像密度变了）；
  仅密度数值变化时才补/砍差额，避免拖滑块时整屏闪一下。
  倍率实时作用在绘制上，**不重建粒子池**；
  它只管背景星光，**不影响流星头**（头部大小是独立的 `kMeteorHeadMin..Max`）；
  数量变化只补/砍差额，避免整屏闪一下重铺。`0` 不是「留白」而是「关掉这层」：
  网页端连 `#fx` 画布都不建、rAF 也不启动（只在还勾着 USTC 弹字时留着跑字母）。
  行末的数值不是纯文本，而是**可单击输入的框**（与 `DOUBLE-CLICK` 的毫秒框同一套机器：
  虚拟焦点 id **11=密度、12=大小**，`settingsChar` 逐字符校验、越界的字符当场被拒）。
  提交口径两端各自沿用**自己**毫秒框的现规矩，没互相改：桌面端**失焦即提交**
  （`settingsFocusOn(0)` / Esc / 关面板都走一遍提交校验），网页端**Enter 提交、Esc 只丢缓冲**。
- **登录页也有一层星光**：`web/gate/index.html` 的 `<canvas id="fx" aria-hidden="true">`
  + `gate.js` 末尾**自包含**的一份最小粒子。它绝不能 `import dist/fx.js` —— 那个文件收在
  闸门内，匿名访客请求它就是 404，而登录页恰恰是给匿名的人看的。登录页这层只飘只闪，
  **没有** USTC 弹字（页面上没有那个复选框，门控无从谈起），也**刻意打折**：
  数量按同一套密度公式换算后 `min(160, …)`、倍率 `starScale × 0.75`，且**没有流星 / 耀斑 / 单位圆彩蛋** ——
  密码页要安静，不能抢走「输入密码」这一件事的注意力。`starDensity = 0` 时登录页也照办，连画布都不建。

#### 2026-10-20 视觉重写：从「纸面灰尘」到「会发光的星」

改之前那层是均匀小圆点 + 线性闪烁，落在浅色默认背景上几乎看不见，看着像屏幕上的灰。

| `kTrailHeadW` / `kMeteorGlow` | 0.1 / 9 | 尾巴头部半宽 / R（发丝级）；头部光晕直径 = R × 9（alpha 收到 0.72，别把格子数字洗白） |

| `kRiseMin` / `kRiseMax` / `kDtCap` | 5 / 19 / 0.05 | 上升速度与每帧 `dt` 上限（**未改**，与重写前一致） |

流星的速度**不是**一个独立常量：出生时先量「沿这条射线还能走多远才彻底出屏」`D`，
再取 `sp = D ÷ 寿命`。所以过屏时间精确等于寿命（3–4.5 秒），窗口大小只改变快慢、不改变停留时长；
飞行途中改窗口尺寸不重算，出屏即杀仍然兜底。

流星头的大小是**出生时随机一次**存进 `Meteor::headR`（两端同构），不是每帧算 —— 每帧随机会让头部
一帧一个样地抖。它**不吃** `starScale` / `STARS · SIZE` 滑块：那个滑块的语义是「背景星光多大」，
把它拉到 3.0 时背景星会很大、流星头照旧。画序是「尾巴 → 柔光 → 四芒 → 细环」。

调参只改这一张表里的数字，三处（`Renderer.cpp` 的 `namespace starfx`、`web/ts/fx.ts` 的
`const starfx`、`web/gate/gate.js` 的 `FX` 子集）必须同时改；T57 会逐项抽值互比。

三条铁律（改这个文件之前先读）：

| 铁律 | 为什么 |
| --- | --- |
| `#fx` 必须 `pointer-events: none` | 漏了这一层就吞掉棋盘全部点击，游戏直接不能玩 —— 比「没有特效」严重得多。登录页同理，否则密码框点不动 |
| 监听器默认**只听不拦**：`capture: true` 先读坐标，再把事件原样交回游戏。**唯一例外**：左键正好打中流星时吞掉这一击（`preventDefault` + `stopPropagation`），因为「炸圈的同一刻还把底下的格子翻开」是错的体验；右键、空地、触摸/笔一律放行 | 游戏对右键调过 `preventDefault()`，冒泡阶段读不到坐标，所以要在 capture 阶段先读；不吞击的话流星就成了「点不动的装饰」，一吞就吞掉一整格的操作，所以只在命中判断为真的那个分支里吞 |
| 不加 `z-index` | 本仓库约定 DOM 顺序决定层级，特效层排在最前 → 后插入的对话框仍在它上面 |

另外：`prefers-reduced-motion: reduce` 时整层不启用；标签页切到后台（`document.hidden`）
暂停 rAF；每帧 `dt` 钳到 0.05 秒，防止长时间挂后台后一次性放出一大堆。
产物 `dist/fx.js` 是同源脚本，已进 `deploy-web.sh` 的校验和清单与「未登录必须 404」清单，
缓存击穿（`?v=BUILD`）由 `main.js` 里的相对 import 自动带上。

#### 桌面端同源实现（2026-10-20）

桌面端原来什么都没有，这层是净新增的：`Renderer::drawFx()` 画在 `drawOverlay()` 之后、
`drawMenu()` **之前** —— 网页端靠 DOM 顺序拿到「盖棋盘但不盖模态面板」，桌面端只能靠调用顺序，
顺序写错就是设置面板被星光穿过去。粒子模型与 `fx.ts` 逐条对齐（幂律半径、三色权重、
光晕 + 星核两层、`pow 6` 闪烁、大星画内凹 ✦、飘出上边缘就从**下边缘**补进来、字母池上限 32）。
桌面端的光晕是启动时用 `sf::Image` 逐像素算出来的一张 64×64 贴图（`ensureGlowTex()`，
只建一次），网页端则是 `createRadialGradient` 的三个色标 —— 实现不同、数值同源。
两端都过 `displayColor()` 做 sRGB→Display-P3 预补偿，否则广色域屏上蓝色会偏艳。
流星两端同一条公式：泊松间隔 + 解析回推的衰减尾迹，**不存历史**，所以掉帧不会拖出断线。
速度由「出生点→出屏距离 ÷ 寿命」导出，屏幕上停留 3–4.5 秒、尾巴是 0.6–1 秒走过的路程
（旧版是固定 400–700 px/s + 0.16 秒拖尾，两秒不到就窜出去了）。

桌面端 `starDensity = 0` 的口径（与网页端一致）：清空粒子池、不画星也不放流星，
但 **USTC 弹字照旧**（字母只受那个复选框门控，不受星光密度影响）。

**「打中流星就吞掉这一击」两端同一条规则**，只是落地方式不同：网页端在 capture 阶段
`burstMeteorAt()` 返回 true 才 `preventDefault()` + `stopPropagation()`；桌面端 SFML 没有
「吞事件」这回事，`main.cpp` 拿到 `MouseButtonPressed` 后先问 `renderer.fxRipple(px)`（命中
就把那颗星从池里摘掉并炸一圈，返回是否命中），命中则 `continue` 跳过后面整套按钮/格子判定。
命中半径两端同式：`headR × kRippleHit`（星头才 10–14px，不放宽在宽屏上几乎点不中）。
只吞左键：右键插旗与点空地一律照常，弹字（`fxBurst`）在吞不吞之前都做，所以炸圈那一下
仍然会闪出字母。

两条桌面端特有的坑，改动时别踩：

| 坑 | 后果 |
| --- | --- |
| 字母循环必须 `++it` | 漏掉 iterator 递增不会死循环（寿命会在同一帧被扣光），表现为**字母当场消失、屏幕上永远看不到弹字**，测试还全绿。T57 有专门一条钉它 |
| 装饰随机数用独立的 `std::mt19937(std::random_device)` | 绝不能借用游戏的种子 RNG —— 「同一个种子复现同一局」是硬约束，为了几颗星星把它打破不值 |

**默认值与区间四处各写了一份**（`web/ts/settings.ts`、`src/desktop/SettingsIO.h/.cpp`、
`src/desktop/Renderer.h`），同一份配置必须在两端表现一致。T57 不再把数字写死在断言里
（写死就会「改一次默认值要同时改代码和测试」，而且改漏了测试反而变绿），
而是**从各端源码里各抽一遍再互比**：`kStarDensityMin/Max`、`kStarScaleMin/Max`、
两个默认值、`SettingsIO.cpp` 读入后的夹取上界、`gate.js` 的判定上界必须全部相等；
`settings.ini` 另外单独认旧刻度的 0..800 上限与 `starunit = 2` 标记。
密度精确到两位小数（0.01 步进）：滑条步进、setter 收拢（`×100`）、读数格式（`toFixed(2)` /
`setprecision(2)`）、输入框容量（4 字符，够输 `7.12`）四项也必须成套，否则会出现
「滑条只能出 2.2、默认却写 2.17」这种自相矛盾的读数。
桌面端 `settings.ini` 的键名是小写 `stardensity` / `starscale`，非法值按既有设计**拒绝并保持默认**（不夹取）；
旧版键 `starcount` 仍然读入，和没有 `starunit` 的 `stardensity` 一样按旧刻度折算。
新写的配置一定带 `starunit = 2`（网页端是 `starUnit: 2`），下次读入就不再折算。

观感参数（上面那张表）另有两条 T57 断言：桌面 `namespace starfx` 与网页 `const starfx`
**逐项抽值互比**（含三个颜色：桌面 `displayColor(r,g,b)` ↔ 网页 `'#rrggbb'`），
`gate.js` 的 `FX` 必须是网页那份的**子集且同数**，并且不得出现流星 / 耀斑 / 单位圆的键 ——
登录页那层是刻意打折的，多出来的键就是「偷偷把游戏页的热闹搬到了密码页」。

#### 怎么调这层的观感（`web/test/fx-look.mjs`）

「好不好看」没法用断言写死，所以调参靠一条 CDP 采样回路：起 `serve.py`（**无闸门**）+

## 两条必须守住的铁律（都是线上事故换来的）

### 1. 受保护的响应**绝不能**带长缓存

nginx 里**正则 location 压过普通前缀 location**，所以 `location /dist/` 挡不住  
`location ~* \.(js|css|...)$`。曾经那条正则带着 `expires 7d`，结果是：

- 浏览器 7 天内**一个请求都不发**就用缓存里的 `dist/*.js`；
- 游戏 HTML 也没有 `Cache-Control`（只有 ETag/Last-Modified），浏览器按启发式新鲜度直接复用；
- 于是**直接在地址栏输网址就能不登录进游戏**，`auth_request` 没机会跑，只有 F5（强制重新校验）才弹密码页。

规矩：**凡是挂了 `auth_request` 的 location 都不许出现 `expires`**，必须  
`no-store`（HTML 入口）或 `no-cache, private`（JS/CSS，带 ETag 仍可 304，不重传正文）。  
给子块加 `add_header` 会让父块的安全头失效，所以这些块都要重新 `include` 安全头。  
`deploy-web.sh` 的自测会在**未登录的 404** 上断言这条（`add_header ... always` 对错误响应同样生效，  
不需要密码就能守住），并额外扫描配置里有没有「带 auth_request 又带 expires」的 location。

### 2. 改完一定要 `push`，工具会替你盯着

`add` / `passwd` / `rm` / `disable` 都只写本地文件，线上要 `push` 才生效。  
工具用 `~/.cmsgate/.pushed` 记录最后一次成功推送的指纹，任何改动密码表的命令与 `list`  
的末尾都会醒目告警。另外两个护栏：

- `push` 拒绝把 **gen 推回更小的值**——注意方向：gen 降回旧值不会"踢人"，而是让  
  **已经被踢掉的旧 cookie 重新生效**（误放行）。典型误操作是 `revoke-all` 没推、又 `pull` 了一次，  
  本地 gen 被拉回旧值，随后 push 就把它降回去了。除非 `--force`，否则拒绝；
- `pull` 是覆盖式的，若会丢弃本地未推送的条目（或改写 gen），会先列出来并**中止**，除非 `--force`。

### 3. 谁会掉线？只有这五种操作

会话 cookie 里记着 `pwid`（哪条密码）+ `rev`（该条密码的版本）+ `gen`（全表版本），  
服务端**每次请求**都重新比对这四个字段（还有 `enabled` / 过期时间）。所以：

| 操作                             | 会不会踢人  | 踢谁                          |
| ------------------------------ | ------ | --------------------------- |
| `push`（普通，例如 `add` / `note` 后） | **不会** | —— gen `rev` 都没变，服务端重载后照旧放行 |
| `passwd <id>`                  | 会      | 只用这一条密码登录的会话                |
| `rm <id>` / `disable <id>`     | 会      | 同上                          |
| `expire` 到期                    | 会      | 同上（到点后下一次请求就拒）              |
| `revoke-all`                   | 会      | **所有人，包括你自己**               |
| `gate off`（总开关）               | 不踢人    | 但**任何人免密即可进入**——比踢人更危险的方向    |

也就是说：**"普通 push 把浏览器弹出"不会发生**；真被弹出去，一定是上面那四种之一生效了。  
如果 `revoke-all` 是刚跑的，那"弹出"就是它干的——它本来就该这样，只是**你自己也在"所有人"里**。

### 4. 总开关与 key 的生命周期

**总开关**（服务器上的 `gateconfig.json`，mtime 热重载，改完立刻生效，不用重启服务、不用动 nginx）：

```bash
cms gate status    # 现在是开还是关、管理口令设没设
cms gate off       # 任何人免密进入（维护/内测期用）
cms gate on        # 恢复成需要密码
```

切换**两个方向都要校验管理口令**，口令只从 stdin / 隐藏输入读，绝不进 argv：

```bash
cms admin-init     # 首次设置管理口令（≥12 位，输两遍）
cms admin-passwd   # 更换管理口令
```

**单条 key 的生命周期**（都不用碰总开关）：

```bash
cms disable <id>   # 停用：该条已登录的会话下一次请求立即失效，记录保留
cms enable  <id>   # 重新启用（gen/rev 没变，所以原来那些会话又有效了）
cms expire  <id> --days 7     # 7 天后过期
cms expire  <id> --until 2026-11-01   # 到 11-01 当天结束（UTC）
cms expire  <id> --never      # 取消有效期
cms show <id>      # 看这条自己的详情 + 它自己的访问记录
```

被停用 / 已过期的用户会看到**各自的**提示（「已被停用」/「已过期」），
不会显示成"密码不正确"——否则他会一直重试一个永远过不去的密码。

## 谁能操作这个工具？**两道门，缺一不可**

先回答一个常见误解：**「只有拿到 SSH 私钥的人才能操作」——只对了一半。**

| 操作类型 | 需要 SSH 私钥 | 需要管理口令 |
| --- | --- | --- |
| `list` / `show` / `usage` / `init` / `selftest` | 否（纯本地读） | 否 |
| `add` / `rm` / `disable` / `enable` / `expire` / `passwd` / `note` | 否（纯本地改表） | **是** |
| `push` / `pull` / `revoke-all` | **是**（要连服务器） | **是** |
| `gate on` / `gate off` | **是** | **是**（它自己的实现） |
| `admin-init`（首次设口令） | **是** | 否（此时还没有口令） |
| `admin-passwd`（换口令） | **是** | **是**（先验「当前口令」） |

**两道门挡的是完全不同的东西，别混为一谈：**

- **SSH 私钥**（`BatchMode=yes` + 服务器只收公钥）挡的是**网络上的攻击者**。
  私钥没泄露，工具就完全连不上服务器。
- **管理口令**挡的是**已经拿到你本机用户权限的人**。这一类最容易被忽略：
  能以你的身份跑进程，就能读 `~/.cmsgate/passwords.json`（`0600` 只挡别人、不挡你）、
  能改 `gen`、能 `add` 密码——**而 `push` 只需要敲一下回车**。
  没有第二道门时，「拿到本机的文件」≈「拥有整个网站」。

所以规则很简单：**读操作不要口令，写操作一律要。**

### 写操作时会看到什么

```
$ cms push
管理口令（推送到服务器需要）:          ← 不回显，敲完回车
已推送（本地 sha256 3f9a1c…）——服务端按 mtime 热重载，无需重启。
```

口令错了会**在改动任何文件之前**停下，并明确说「未执行」：

```
$ cms push
管理口令（推送到服务器需要）:
管理口令不正确，「推送到服务器」**未**执行。
  闸门状态： cms gate status
```

### 脚本 / 管道里怎么喂口令

不要写进命令行（`ps aux` 能看到、shell 历史也会留下）——用 `--admin-stdin`：

```bash
cms push --admin-stdin < ~/.cmsgate/admin-pw.txt
# 或
printf '%s\n' "$ADMIN_PW" | cms add --label '给小明' --admin-stdin --password-stdin < 新密码.txt
```

> `add --password-stdin` 的**顺序**是固定的：**先管理口令，再是新密码**。
> 两者都从 stdin 逐行读，所以喂的时候先放管理口令那一行。

**没有** `--no-admin-check` 之类的绕过开关——那等于把这道门重新变成装饰。

### 「先说明、后拒绝」优先于问口令

有些操作在动手之前就该先说清楚，比如 `revoke-all` 没加 `--yes`：

```
$ cms revoke-all
revoke-all：让**所有**在线会话立即失效——包括你自己此刻开着的那个浏览器。
  …（完整说明）…
  注意：确认执行时还会要求**管理口令**（它会踢掉所有人，值得多一道确认）。
已中止，未改动任何文件。确认要踢人（含你自己）请加 --yes。
```

它**不会**先问口令才告诉你「你忘了加 `--yes`」——那会让人以为自己口令输错了，
反复重输一个根本没输错的口令。

## 可视化界面（`tools/gate_ui.py`）

不想敲命令时用这个。**只在本机可访问**，管理同一份 `~/.cmsgate/passwords.json`。

```bash
python3 /Users/wenweiqi/CLionProjects/Project/tools/gate_ui.py           # 默认 127.0.0.1:8730
python3 /Users/wenweiqi/CLionProjects/Project/tools/gate_ui.py --port 8731
python3 /Users/wenweiqi/CLionProjects/Project/tools/gate_ui.py --no-pull  # 不自动从服务器拉访问记录
```

**不需要 cd，而且必须用绝对路径。** 数据在 `~/.cmsgate/`，与当前工作目录无关——
和 `cms` 完全一样。

> `--server / --ssh-port / --remote-dir` 现在会**原样传给子进程**。以前只传 `--state`，
> 于是界面顶栏写着「服务器 A」、push 和 `usage --remote` 实际却连 CLI 的默认服务器——
> 一个不报错但很要命的不一致。

> 反例：在 `~` 下敲 `python3 tools/gate_ui.py` → `No such file or directory`
> （那个相对路径指的是 `~/tools/`，不是你 checkout 的仓库）。

启动后终端会打印一条网址：

```
http://127.0.0.1:8730/?k=<一次性 token>
```

**必须用这条完整网址打开**——直接敲 `127.0.0.1:8730` 会看到「需要钥匙」的提示页。
这不是 bug，是刻意设计的（见下面的四层防护）。token 每次启动都不一样，进程退出即失效。

> ⚠️ **改过 `gate_ui.py` 就必须重启进程**（Ctrl-C 再 `cmsui`）。
> 前端资源（`index.html` / `app.js` / `app.css`）是**每次请求从磁盘读**的，刷新即生效；
> 但 `gate_ui.py` 本身是被 Python 载入内存的，**改完不重启，接口还是旧的**。
> 这种不一致极其难猜——2026-10-17 就踩过：新前端调新接口、旧进程不认参数，
> 结果是「时间列能筛、其他列的面板全空」。现在页面会自己说：顶栏出现红字
> **「服务端代码已更新 / 重启 cmsui 生效」**；列头面板取不到可选值时也会把错误打出来，
> 而不是只留一个「（全部）」。

> 反馈是「这个按钮点不动」。改成对话框并且**先画骨架、再取数据**，点击立刻有反馈。
> `T21` 用静态断言守着这条，防止以后又被「简化」回去。

### 管理口令输错不用从头再来

写操作要口令。**口令错了界面不会退出**，而是带着「管理口令不正确 · 重新输入」的提示
把口令框重新弹出来——**之前填的标签/备注/有效期/长度全都还在**，重打口令就行。
只有在口令框里按「取消」才会中止。

判错用词是精确的：只认 CLI 的 `管理口令不正确`。
`服务器上没有管理口令，无法执行…` **不算**口令错（那种情况重输一百遍也没用，该去 `admin-init`）。

### 最近访问：最新的在最上面

按 `ts` 排序，**不依赖缓存文件的写入顺序**——
真实缓存是 `tail -n N usage.jsonl` 出来的（追加序 = 时间序），但把这个当前提迟早出事：
缓存哪天被合并/重写过，页面就会「最新的不在最上面」而且**一声不响**。
`ts` 是定长 UTC ISO 串，字典序就是时间序，直接排即可。（CLI 的 `cms usage` 仍按正序打印，
那是日志的读法；表格是给人扫的，方向相反。）

### 所有密码列表：创建时间从晚到早

三处统一按 `created_at` **倒序**（最新的在最上面）：

1. 页面最上方的**密码条目表**
2. 密码列下拉里的**密码列表**
3. CLI 的 **`cms list`**

此前是正序。两处方向不一致会让人对着两个屏幕数半天，所以一起改了。
下拉里的次要顺序：**现存的排最前**（那才是要挑的），已删除的其次（表里没有 created_at，
只能按出现次数排），没有 id 的匿名记录排最后（它不具备「密码」的语义）。

### 列头筛选（点 ▾）

每一列列头右边有个小 **▾**，点开是**这一列自己的可选值 + 条数**（复选框）。
同一列里多选是「或」，不同列之间是「且」——和 Excel 的自动筛选一个语义。
勾一下**立即生效**（不用点确定），面板可以开着连续勾，看表格实时缩小。
`▾` 变成实心带数字（如 `▾2`）就表示这列筛了 2 个值；标题旁的「清除全部筛选」一把清空。

| 列 | 筛法 |
| --- | --- |
| 时间 | 单选：全部 / 今天 / 最近 7 天 / 最近 30 天 / **自定义起止时间**。「今天」= **本机时区零点**，不是 UTC 零点 |
| 结果 | 多选：成功 / 密码错 / 被限流 / 已禁用 / 已过期 / 失败（其它） |
| 密码 | 多选：**从访问记录本身聚合**，所以**已删除的密码也筛得出来**；显示标签不显示 id。另有「只显示密码表里还存在的」开关（默认开） |
| IP | 多选：出现过的原值（没有明文 IP 时是 `hash:xxxxxxxx`） |
| 浏览器 | 多选：**默认按名字合并**（`Edge`）；关掉合并才按全名（`Edge 155.0.0.0`）。合并时那一项后面标「N 版」，悬停能看到原始串；超过 8 项时面板里带「在列表里找…」 |
| 系统 / 设备 | 多选：`macOS 10.15.7 / Mac` 这种组合值 |

**自定义起止时间**：选「自定义起止时间…」会展开两个 `datetime-local` 输入框。
传给服务端的是**毫秒时间戳**（浏览器 `new Date(v).getTime()` 算出来的，已经带本机时区），
服务端不再做任何时区推断——少一层假设就少一个「差 8 小时」的机会。
**结束时间含整分钟**：选「到 12:00」会包含 `12:00:30` 的记录；不加那 60 秒就会出现
「明明有记录却查不到」。开始晚于结束会**直接报错**，不会静默返回 0 条。

**「只显示密码表里还存在的」（默认开）**：藏掉「有 pwid 但已经不在密码表里」的记录，
下拉里也不再出现那些删掉的测试密码（实测某台机器上 19 项缩到 5 项）。
但**没有 pwid 的匿名失败记录会保留**——那是密码输错时的记录，服务器本来就查不到对应哪条密码，
所以不带 pwid（真实数据里 111/170 条都是这种）。把它们一起藏掉，等于把审计里最该看的东西藏了。

条目表的「状态」列也是同一个机制：多选 启用 / 已禁用 / 已过期 / 有效期非法，
外加一条独立的「只看 7 天内到期」（它是「且」条件，和上面的多选不冲突）。

**浏览器列「按浏览器名合并」（默认开）**：UA 解析出来的串带版本号，同一个人升级一次
浏览器就多一个筛选项。合并规则是「砍掉第一个数字段之前的部分」——
`Edge 155.0.0.0` → `Edge`、`Mobile Safari 17.0` → `Mobile Safari`（**不能**按第一个空格切，
否则会退化成 `Mobile`）。实测某台机器 13 项缩到 5 项。合并是为了列表短，但信息没丢：
选项后面标「3 版」，悬停列出原始串，表格那一列也照旧显示全名。

> ★ **切模式会清掉已选的浏览器值**。两种模式的筛选值不通用（一个要 `Edge`，
> 一个是 `Edge 155.0.0.0`），不清的话切过去就是「拿旧值比新列表」→ 表格静默变 0 条，
> 看起来像数据丢了。同理前端两处查询（`/api/usage` 与 `/api/usage_facets`）
> **必须带同一个 `bname`**，漏一处就是同一个症状。
> 这个开关是**显示模式**，不是筛选条件，所以「清除全部筛选 / 清空本列」都不会把它改回去。

> ★ **为什么不在前端筛**：前端只拿得到「最近 N 条」。若在这 N 条里筛「仅失败」，
> 那么「最近 200 条里没有失败」会被显示成「没有失败」——而 300 条之前可能失败了一大片。
> 审计表格不能出这种静默漏判。所以筛选发生在「取 N 条」**之前**，
> 并且接口把 `total`（总条数）与 `matched`（筛选后条数）一起回给前端，
> 标题旁边显示「共 350 条，筛选后 12 条 · 只显示最近 12 条」，一眼能看出筛掉了多少。

> ★ **每列的可选值来自「未筛选」的全量**（`/api/usage_facets`）。若按当前结果生成，
> 勾了「成功」之后「密码错」会从列表里消失，想改选就得先清空——Excel 不是这么干的。

**空值怎么筛**：老记录可能没有 UA。查询串里空串等于「不限」，所以「只看没记到浏览器的」
用一个显式 token `__blank__`（面板里显示成`（空）`）。

接口：`GET /api/usage?limit=&offset=&since=&from=&to=&result=&id=&ip=&browser=&os=&q=&existing=&bname=&pull=`
→ `{rows, total, matched, offset, limit, pulled_epoch, pull_error, pull_skip_reason, pull_count, pull_skipped}`；
`GET /api/usage_facets?existing=&bname=` 给列头面板用。
筛选参数都是**逗号分隔的多选**（空 = 不限）。
`since` 只接受 `today / 7d / 30d`，其它值 **400**（不静默忽略）。`result=fail` 是
「任何失败」的别名，保留它是为了让「只失败」能一句话说清。

### 访问记录自动拉取（「刷新就应该是最新的」）

日志在**服务器**上，本地拿不到任何推送——`ssh tail` 是唯一途径。所以「实时」这件事
只能做成**定时去问**，而不是等服务端通知。

| 触发 | 什么时候 |
| --- | --- |
| 打开/刷新页面 | 立刻拉一次（`loadAll()` 带 `pull=1`） |
| 自动刷新 | 默认 **10 秒**；可切 5 秒 / 30 秒 / 关 |
| 点「立即刷新」 | 马上拉，并把「为什么没拉 / 拉失败」直接说出来 |
| 从别的标签页切回来 | 立刻补一次（否则看到的是走开之前的旧数据） |

**不该拉的时候不拉**：改筛选条件只是换个看法（缓存里已经有 1000 行），不连 ssh；
切到后台标签页（`document.hidden`）这一轮跳过；写操作（push / 改密码 / 踢人）进行中
也让开——别在人家推表的时候抢同一台机器的 ssh。

**服务端还有一层兜底**（`pull_usage()`）：

- **单飞**：已经有拉取在跑就**直接跳过**，不排队。排队的话自动刷新会越积越多，
  最后变成一串 ssh 排着队跑，页面反而更卡。
- **最小间隔 2 秒**：按钮连点不会打出一串连接。
- **失败不清缓存**：拉不到时表格继续显示上次的数据，标题旁标「同步失败，显示 12:39:41 的数据」，
  鼠标悬停能看到 CLI 的原话。否则一次断网就会把「最近访问」变成空白，看着像记录全丢了。
- `pull_skip_reason` 会告诉界面这次是 `gap`（太频繁）/ `busy`（上次没跑完）/
  `exec`（有写操作在跑）/ `disabled`（`--no-pull`），不是默默什么都不做。

> ★ **拉取的行数和「显示条数」下拉是解耦的**：拉取固定要 1000 行，下拉只决定显示几行。
> 以前两者是同一个值，选「50 条」就会让缓存被裁成 250 行，「共 N 条」跟着变小——
> 而那是审计数据，变小看起来像记录丢了。

不想让它碰 ssh 就加 `--no-pull` 启动：

```bash
python3 /Users/wenweiqi/CLionProjects/Project/tools/gate_ui.py --no-pull
```

### 分页（每页 N 条 + 翻页）

访问记录按「最新在前」分页，**每页条数与自动刷新间隔都是可以直接输数字的框**
（每页默认 **20** 条，自动默认 **30** 秒；范围分别是 1–500 与 1–3600 秒，
越界会被夹回并写回输入框）。底部一条翻页器：
`‹ 上一页` · `第 2 / 4 页` · `下一页 ›` · `回到最新`。

- 旁边有 `⏸ 暂停自动刷新` / `▶ 继续自动刷新`：暂停是**独立状态**，不是把间隔设成 0
  （那样恢复时你设的 45 秒就没了）。恢复的瞬间会立刻拉一份最新的。
- 手动刷新 / 自动刷新 / 点「回到最新」之后，页面**顶部**会有一条「已刷新 · 时:分:秒」，
  3 秒后自己收起来。**拉失败或被 2 秒限速挡下时不弹**（那是报假喜）。
- 两个框的值记在 `localStorage` 的 `ui.pageSize` / `ui.autoSec` 两个键里
  （白名单只有这两个，管理口令绝不进 localStorage）。
- 分页在**服务端**做（`offset`），不是把上千条全拉到前端再切——那样「每页 20 条」
  也得先传 1000 行，而且「共 N 条」会和看到的不一致。
- `offset` 是**筛选之后**的下标，所以翻页与筛选可以叠加。
- **筛选条件一变就回第 1 页**。留在第 4 页会看到空白页，像坏了。
- **翻到第 2 页以后，自动刷新暂停**——新记录插在最前面，会让你正在读的那页整体往后挪，
  读到一半内容突然换掉。回到第 1 页（或点「回到最新」）时立刻补一次，不会漏。
- 「每页 N 条」只影响一屏多少行，**不影响拉取多少行**（拉取固定 1000 行，见上）。

### 为什么「共 N 条」和「筛选后 M 条」天生就不相等

这不是 bug，也不表示你手滑加了筛选。访问记录里有一类默认就被藏起来：
**「有 pwid、但那条密码已经从密码表里删了」的历史登录记录**（删掉的测试密码之类）。
开关在「密码」列头 ▾ 里，叫「只显示密码表里还存在的」，**默认开着**。

- 计数会直接点名：`共 174 条，筛选后 129 条 ·（已删除密码的历史记录 45 条 已隐藏）`。
- 旁边有 **显示全部记录** 按钮，点一下就把它们放出来，两个数字随即相等
  （174 = 174，翻页从 7 页变 9 页）。
- **「清除全部筛选」不会动它** —— 那是筛选条件，这是显示范围。
  关掉它要去「密码」列头的 ▾，或点那个蓝色按钮。
- **无 pwid 的失败记录永远不会被藏**：密码输错时服务器根本查不到对应哪条密码，
  本来就没有 pwid。那些恰恰是排查时最该看的，藏起来等于把审计表掏空一个洞。

### 「（全部）」那个框是三态的

除时间列（它本来就是单选）外，每列面板顶部的 **（全部）** 都是三态：

| 当前长相 | 单击之后 | 含义 |
| --- | --- | --- |
| **✓ 全勾**（初始状态） | 全部取消，**一个勾都不留** | 清空这一列的筛选 → 显示全部 |
| **空白**（一个都没勾） | 全选 | 回到初始状态 |
| **− 部分选中** | 全选 | 取消这一列的筛选 |

- **「全部取消」= 不限**，不是 0 条。所以永远不会出现「勾光了结果变空、
  不知道怎么办」的死胡同。
- 取消掉的**视觉状态会被记住**（关掉面板再打开还是空的），不会偷偷恢复成全勾 ——
  否则你根本看不出这一列曾经被清过。点一次「（全部）」就全选回来了。
- 「清空本列」与单击「（全部）」取消效果一致；「清除全部筛选」则把所有列**复位成全勾**。
- 时间列是 radio 单选（全部 / 5 秒 / 1 小时 / 1 天 / 30 天 / 自定义），
  没有三态「（全部）」。

### 网页背景图（公开授权还没拿到，所以能一键撤下）

背景图的**公开使用授权还没拿到**。在那之前必须能「点一下就撤下来」，而且撤下之后
**原图要从公开目录消失**——只在前端加个开关没有意义，`wget /assets/bg.webp`
照样能拿到原图。

> **2026-10-19 补一层**：这两张图已从公开清单里**收进闸门**（删掉了 nginx 里那两个
> `location = /assets/bg.*` 公开块，落到带 `auth_request` 的正则块）。现在匿名请求直接
> **404**，只有登录后（会话 cookie 是 `Path=/`，覆盖 `/assets/*`）才拿得到。
> 登录页也不再引它，改用 CSS 渐变。也就是说：未授权素材不再对匿名访客分发，
> 而下面这套「一键撤下 / 换图」流程照旧有效 —— 两层是叠加的，不是替换。

顶栏有 `网页背景 开 / 关（白底）` 芯片，点开能看到**当前那张图的预览**和**下载按钮**，
下面是同一个开关 + 一个「推送新图」按钮（选文件 → 本机转码 → 上传覆盖，不用手打路径）。
命令行等价物：

| 想做的事 | 敲这条 | 要管理口令 |
| --- | --- | --- |
| 看现状（开/关、文件大小、有没有私藏备份） | `cms webbg status` | 否 |
| 撤下（游戏画布变纯白底；2026-10-19 起密码页是渐变，本来就不引它） | `cms webbg off` | 是 |
| 恢复 | `cms webbg on` | 是 |
| 换新图（自动转 webp + jpg 后覆盖） | `cms webbg push --image ~/图.png` | 是 |

**预览与下载**走本机的 `GET /api/webbg_image?which=webp|jpg`（`&download=1` 变下载），
经 ssh 从服务器把字节取回来。三点说明：

- **不走线上那个 URL**。一是那会把线上地址摆到页面里；二是撤下之后那张 URL
  变成白图，就永远预览不到原图了（现在它连匿名都不给 —— 直接 404）。
- **有鉴权**（没 cookie → 403），并且 `which` 走白名单、拼 ssh 命令前就拒掉
  非白名单值（路径穿越）。取回来的字节还会按魔数（`RIFF` / `\xff\xd8\xff`）再验一次。
- **必须用二进制方式取**：`gm.run` 写死 `text=True`，会把图片按 UTF-8 解码 →
  `UnicodeDecodeError` 把请求线程干掉，浏览器只看到 `Failed to fetch`。
  凡是「传字节流」的活都不能走面向文本的封装。


做法：把线上那张图挪进 `/var/lib/cmsgate/webbg/`（**nginx 不服务那个目录**），
再把一张几十字节的纯白图放进原来的位置。涉及两个文件，**必须一起换**：

- `assets/bg.webp` —— 游戏 canvas 的内置背景（`web/ts/renderer.ts` 的 `kDefaultBg`）
- `assets/bg.jpg` —— 游戏 canvas 在老浏览器解不开 webp 时的兜底
  （**以前它还是密码页的 CSS 背景，2026-10-19 起密码页改用渐变，不再引它**）

**三条边界（界面里也写给用户看）**：

1. **已经加载过图的浏览器，内存里仍有那张图**——浏览器行为，撤不回来。
   新访问 / 刷新才会看到白底。
2. **缓存头要配合，而且必须是 `no-store`**。这个文件改过两次，每次都是被实测打脸：

   - **第一版 `expires 7d`**：已访问过的访客最长 7 天不重新请求 → "关掉了却没变白"。
   - **第二版 `no-cache, must-revalidate`**（2026-10-17 15:52 部署）：**仍然不够**。
     访客浏览器手里那份**旧响应自带 `expires: 7d`**，客户端**根本不看服务器后来改的头**。
     实测 2026-10-17 16:31：换了图，普通刷新仍显示旧图，**只有 ⌘⇧R 强刷才对**。
     `no-cache` 只管「下次回源」，管不了「已经存着的」。
   - **第三版 `no-store`（当前）**：任何客户端都不许存。换图后普通刷新即生效，
     没有 7 天尾巴。代价是每次都重传 ~136 KB（`webbg push` 已把长边压到 1920）。

   实测（当时这条 URL 还公开；**现在匿名是 404，要看头得带会话 cookie**。
   而且 `IP:8080` 已在 2026-10-20 收回回环，下面这条原样复制会连接被拒 ——
   换成 `https://ty0712.com/assets/bg.webp`，或开一条隧道再看）：

   ```
   $ curl -sD- -o/dev/null http://<服务器IP>:8080/assets/bg.webp | grep -iE 'expires|cache-control'
   Cache-Control: no-store                                  ← 没有 Expires 头
   ```

   ★ 这是刻意取舍：版权未授权时，「撤下要立刻且彻底生效」比省流量重要。

   别写 `expires 0`：它会自己再发一个 Cache-Control 头，与 `add_header` 叠成两个。
3. **再跑 `deploy-web.sh` 会把背景图覆盖回去**（`rsync --delete` 会同步本地
   `web/assets/bg.webp` 与 `bg.jpg`）。所以**推完新图必须把本机那两张也换成同一张**，
   否则下一次部署会把线上的新图无声地推回旧的。`webbg status` 会检出这种漂移。
   - 换本机那两张的办法：`/api/webbg_image?which=webp|jpg&download=1` 各存一份到
     `web/assets/`（本接口要鉴权，从 cmsui 里存最省事）。
   - 顺带一条：`gate_manager.py` 的 `DEFAULT_WEB_ROOT` 与 `deploy-web.sh` 的
     `REMOTE_DIR` 必须一致（selftest 有断言盯着），否则背景图会推进一个没人访问的
     目录，而且**scp 不报错、看起来完全成功**。

推送时**两张图必须一起换**（`webbg_encode` 里 jpg 转不成功就直接报错，不许只推一张）：
少一张的后果是密码页或老浏览器继续显示旧图——那正是"以为已经撤干净了"的假象。

**长边会被压到 1920**（`WEBBG_MAX_EDGE`，改这个常量即可）。原因：密码页是
`background-size: cover`、游戏 canvas 也是拉伸铺满，**任何超过屏幕的分辨率都是纯浪费**
（cover 还会把溢出部分裁掉）；密码页还有 `background-attachment: fixed`，
图越大滚动越卡。实测同一张图：

| | webp | jpg |
| --- | --- | --- |
| 4800×2738（原始尺寸） | 511 KB | 1.72 MB |
| **1920×1095（自动压缩后）** | **136 KB** | **426 KB** |

省 74% / 76%，1440 屏上**看不出差别**。已经够小的图不会被重编码（缩放本身会掉画质）。
缩图失败不会中断推送——继续用原图，只是大一点。

**原图也存一份到服务器**（`/var/lib/cmsgate/webbg/source.<扩展名>`，权限 600）。
转码后 1920 的 webp 就丢了细节，日后想换尺寸 / 换质量重新转码时原图在手才不用再找。

- 服务器上**只留当前这张**：推新图会先删掉旧的 `source.*`，不按时间戳堆历史
  （原图动辄 5–6 MB，堆几次就撑爆磁盘）。
- **服务器上不留任何临时文件**：原图先传到 `{remote_dir}/webbg-source.tmp`，
  核对字节数（scp 中断会留半个文件）后 `mv` 进私藏目录；失败路径另有一条 `rm` 兜底。
- **本机 `state/uploads/` 只留最近 10 张**（`WEBBG_UPLOAD_KEEP`），按 mtime 裁剪，
  只删 `bg-` 前缀的 —— 目录里别人的文件一个不动。每次推送输出的清单里会说明删了哪些。



### 「有改动未推送」到底是哪几条改了

顶栏那个 `同步 有改动未推送` 芯片是**可点的**——点开逐条列出：

| 类型 | 含义 | 推送后会发生什么 |
| --- | --- | --- |
| 新增 | 本地有、线上没有 | 对方才能用它登录 |
| 删除 | 线上有、本地删了 | 这条立即失效 |
| 修改 | 两边都有但字段不同 | 以本地为准覆盖线上 |

「修改」会点名改了哪些字段：**标签 / 备注 / 启用状态 / 有效期 / 轮换次数 / 密码**。
对话框底下直接给一个「去推送这 N 项改动」按钮。

**比的是线上那份，不是「上次推送时的快照」。** 因为 `.pushed` 只存了一串 sha256、没有内容，
「相对上次推送改了什么」本身算不出来（除非另存快照）。而用户真正要知道的是
**线上现在还缺哪些改动**——「未推送」意味着访客此刻看到的还是旧表。
顺带还能发现 `.pushed` 标记察觉不到的情况：**别的机器推过**（本机标记说「一致」，
但线上那份不一样，界面会单独提示）。

> ⚠️ 比对在**服务端**做，返回给前端的只有「这条的密码变了」这句话，
> **salt / hash 一个字节都不外传**。`T24` 有一条断言直接把返回值 `json.dumps` 出来搜哈希。
>
> 还有一条容易写错的分支：`remote_read_json` 用 `None` 同时表示「线上没有这个文件」和
> 「ssh 连不上」。前者是首次推送（本地全部算新增），后者必须**报错**——
> 把「连不上」显示成「线上什么都没有」，用户会以为自己的密码全丢了。`T24` 也守着这条。
>
> 每次点开要连一次 ssh（约 1~2 秒），对话框会先显示「正在连服务器逐条比对…」。

### 四层防护：为什么必须带 token

本地起了 HTTP 服务之后，**浏览器里任意一个网页都可能向 `127.0.0.1:端口` 发请求**。
而这个工具能改密码、能踢人、能开关整站闸门——被跨站请求打一次就是全站失守。
所以有四层，每一层对应一种真实手法：

| 层 | 挡什么 | 怎么做 |
| --- | --- | --- |
| 只绑 `127.0.0.1` | 局域网里别的机器 | 不是 `0.0.0.0` |
| 一次性 token | 别的进程/网页猜不到 | 启动生成；校验后换成 `HttpOnly; SameSite=Strict` cookie，并把 token 从地址栏抹掉 |
| **Host 头白名单** | **DNS rebinding** | 攻击者把自己的域名解析到 127.0.0.1，浏览器以为是同源；但它发的 `Host` 是那个域名，被拒 |
| `X-CMSUI: 1` 自定义头 | CSRF | 跨站表单发不出自定义头；带自定义头的跨站请求会触发 CORS 预检，本服务不响应预检 |

外加：响应一律 `no-store`、CSP `default-src 'self'`、`X-Frame-Options: DENY`。

> ⚠️ 打印出来的网址**不要贴给别人**——它就是钥匙。要给别人临时用，给对方单独 `add`
> 一条访问密码，而不是把管理界面的地址发过去。

### 界面不做权限判断（重要）

界面的写操作**全部转调原 CLI**（`subprocess`），管理口令通过 stdin 喂（`--admin-stdin`），
**不进 argv**。「哪些命令需要口令」是从 `gate_manager.ADMIN_GUARDED_CMDS` **导入**的，
不在这里另抄一份。

所以：

- 真正的校验永远发生在 `gate_manager.py` 里，**界面没有任何办法绕过那道门**；
- 口令错了会在动文件之前停下，界面只是把 CLI 的原话显示出来；
- 关掉界面，`cms` 那套命令一个字都没变。

### 启动自检

启动时会跑 `_verify_ops()`，用**每个命令自己的 `--help`** 核对界面这张表的参数是否真被接受。
对不上就**拒绝启动**，而不是让用户点了按钮才看到一句报错。它检查三件事：

1. 界面用到的子命令都存在；
2. 界面拼的每个 flag 都被那个命令接受（`gate on` 用的是 `--password-stdin`，
   普通写操作是 `--admin-stdin`——**两类不一样**，写错就点不动）；
3. 受管理口令保护的命令必须喂了管理口令那一行。

一打乱就全错（我第一版实现正是 `reversed(recs)`，被这条抓出来了）。
`T23b` 再走一遍真实 HTTP，确认查询参数真的接到路由上（纯函数对 ≠ 拼参数对）。

`T24` 测「未推送的差异」：新增 / 删除 / 修改 / 未变的判定，以及两条**安全断言**——
返回值里搜不到 salt/hash；ssh 连不上时必须是 `reachable=False` 而不是「线上是空的」。
注入过「把指纹塞进返回值」和「连不上也返回 rows」两处错误 → 2 条断言变红。

`T25` 测列头筛选：facet 的取值/条数/文案、多选（同列或 / 跨列且）、
**facet 不随筛选缩水**、以及「只看空值」的 `__blank__` token。
注入过「多选退化成单选」和「facet 只扫前几条」两处错误 → 8 条断言变红。

`T26` 测自定义起止时间、只显示还存在的、创建时间倒序。
两条值得一提的写法：
· 期望值**从测试数据推导**（用定长 ISO 串的字典序数一遍），不手敲常量——
  我手数「10-15 那批有 1 条」实际有 4 条，四条断言一起假红过一次。
· 「结束时间含整分钟」用**差分断言**：`含整分钟 == 严格到秒 + 1`，
  不依赖我数得对不对。
注入过 5 处错误（去掉 +60s、把匿名记录也藏掉、条目表改回正序、CLI 改回正序、
下拉不按创建时间排）→ 7 条断言变红。

`T27` 测浏览器「按名字合并」：10 个名称提取用例（含 `Mobile Safari` 与「只有版本号」）、
合并后条数是否等于几个版本之和、`versions`/`examples` 有没有把信息留住、
以及★**两种模式的筛选值不通用**（合并时 `browser=Edge` 命中 5 条、不合并时命中 0 条）——
这条是防「勾了浏览器就静默 0 条」的。再走真实 HTTP 验 `bname` 真接到路由上，
并静态断言前端**两处**查询都带它。注入 4 处错误（名称退化成「取第一个词」、
路由漏 `bname`、facet 不带 `versions`、切模式不清空选择）→ 4 条断言变红。

`T28` 测自动拉取。分三层，**全程不碰网络**：
· 纯逻辑（把 `run_op` 换成假的）：拉的是 `usage --remote` 且要 `PULL_LIMIT` 行、
  2 秒内重复拉要跳过、失败时**不清掉「上次成功时间」**、`--no-pull` 要明说、有写操作在跑要让开；
· 真 HTTP：起一台 `--no-pull` 的服务，验 `pull=1` 确实走到拉取、且**拉不到时照旧返回缓存里的行**；
· 前端静态：旧复选框必须**消失**（只加不删也是 bug）、`pull=1` 有发、`document.hidden` 有判、
  `apply()` 里**不带** `pull`。
注入 5 处错误（去掉最小间隔、失败时清掉成功时间、不理会写操作、路由忽略 `pull`、
前端不发 `pull=1`）→ 5 条断言变红。

`T29` 测分页与「服务端代码过期」提示：逐页拼接必须等于一次取全（不重不漏、顺序一致）、
越界页返回空行但 `matched` 不变、HTTP 的 `offset` 真接上且非数字是 400；
`stale` 用**挪 `STARTED_AT`** 的方式验（不去改文件的 mtime）。
注入 5 处错误（忽略 offset、offset 恒为 0、`_code_stale` 恒 False、
翻页后仍自动刷新、筛选后不回第 1 页）→ 7 条断言变红。

另外，**每次改完界面都要用无头浏览器真点一遍**（`/tmp` 下的一次性 CDP 脚本）：
列头面板有选项、翻页按钮真的换数据、没有控制台异常。纯静态断言查不出「面板全空」
这类问题——它恰恰是后端 500 被前端吞掉造成的。

测试全部用**临时 `--state` 目录**，不碰真实密码表；写操作用 `--offline-admin-config`
指一份本地假 gateconfig，所以不需要连服务器。需要 SSH 的分支一律用 `--no-pull` 或替换
`run_op` 来隔离——**测试绝不连真服务器**。

> ⚠️ 2026-10-21：这个开关以前是一个**环境变量**，改成了显式 argv 参数，理由写
> 在 `require_admin` 的注释里 —— 环境变量会被任何子进程继承，谁 export 过一次忘了取消，

### 同一密码的多条目：重复组与 cmsui 底色（2026-10-30）

两条密码设成了同一个明文时（比如先建一条后来又照抄建了一条）：

- **登录不再被挡**：authd 选条目优先命中「启用且未过期」的那条；只有所有命中
  都不可用才报停用/过期（旧实现按表序取第一个命中，一停用一启用会把人挡在门外）。
- **自动检测**：`add` / `passwd` 这两个手里有明文的时刻会逐条 scrypt 比对现存
  条目，发现相同就写 `dup` 字段（重复组锚 id）进密码表，并提示 ⚠。
- **存量补标**：条目里只有独立盐的哈希，事后从数据上比不出"密码相同"——
  存量重复用 `cms dupmark <id> <id>…` 手动圈组（`--clear <id>` 移出）。
- **cmsui 底色**：条目表里同一重复组的行画同一浅底色（16 色色板，相邻行撞色
  自动顺延），只此一条的保持白底。组里只剩一条（其他被删/出组）就不算重复。
- 登录优先级修复与 `dup` 字段都要 `push` 后才在线上生效（authd 对未知字段
  宽容，旧版 authd 读到 dup 也不报错）。

`push` 是**原子且可回滚**的：先传 `.new` → 远端 `json.tool` 预校验 → 备份现有 →
`mv` 替换。服务端按文件 mtime 热重载，**不需要重启服务**。
空表会被拒绝推送（除非 `--force`），避免"手一抖所有人都进不去"。

### 访问密码怎么定：三种来源

`add`（新增）和 `passwd`（轮换）**都支持自己定密码**，三种来源**互斥**：

| 写法                  | 行为                                         | 适合                 |
| ------------------- | ------------------------------------------ | ------------------ |
| 什么都不加               | **随机生成**一个 24 位强密码（已剔除 `0/O/1/l/I` 这类易混字符） | 发给别人用的密码（你也记不住，正好） |
| `--password-prompt` | 交互式输入，**不回显**、要输两遍确认                       | 自己想记的密码（推荐）        |
| `--password-stdin`  | 从 stdin 读**一行**                            | 脚本、批量、从密码管理器/文件喂   |

```bash
cms add --label "给我自己" --password-prompt
cms passwd 7adadbc64d18 --password-prompt
```

**为什么不许写 `--password 明文`？** 命令行参数（argv）对同机**任何进程**都可见  
（`ps aux` 一眼就看到），还会进 shell 历史——等于把密码贴在墙上。  
所以工具**从不从 argv 读密码**；真写了会被**明确拦下**并告诉你改用哪个参数，  
而不是甩一句 `unrecognized arguments`：

```
错误：密码不要写在命令行里：`ps aux` 能看到、shell 历史也会留下。
  改用 --password-prompt（不回显地输两遍）或 --password-stdin（从文件/管道喂）。
```

下限 **12 个字符**（中文按 1 个字算），不够时会告诉你差几个、以及三条出路。  
`gate` / `admin-init` / `admin-passwd` 的管理口令同理（默认交互式不回显输入）。

### 两个显示约定（不是 bug）

- **时间默认按本地时区显示**。存储与传输一律 UTC（`%Y-%m-%dT%H:%M:%SZ`），  
  但 `list` / `usage` 直接印 UTC 会让 GMT+8 的人看到"8 小时前"的时间、误以为记录是昨天的。  
  想核对存储原值加 `--utc`。
- **表格按显示宽度排版**（CJK 记 2 列）。按 `len()` 补齐会让表头与数据行错位：  
  `标签` 的 `len` 是 2 但占 4 列。`selftest` 里有断言守着这条，  
  以及「创建列必须 ≥ 19 字符宽」——时间戳一旦换成完整的 `YYYY-MM-DD HH:MM:SS`，  
  列宽忘了跟着加就会顶破表格。
- 超宽单元格（如 64 字符标签）**不截断**，那一行会变宽：宁可挤一点，也不隐藏信息。

## 域名接入：`http://ty0712.com/`（2026-10-20，ICP 备案下来之后）

备案通过、明文收口（2026-10-20）之后，`deploy-web.sh` 生成的是**两个 server 块**：

```nginx
server {                                            # 块一：80 明文只负责送人去 https
listen 80 default_server;  listen [::]:80 default_server;
location ^~ /.well-known/acme-challenge/ { … }      # 唯一还 serving 内容的路径
location ^~ /gate/ { return 404; }                  # 明文上不留登录入口
return 302 https://ty0712.com$request_uri;          # 写死域名，不用 $host
}
server {                                            # 块二：内容
listen 127.0.0.1:8080;   listen [::1]:8080;        # 只绑回环：自己人用的口子
server_name ty0712.com www.ty0712.com;
include /etc/nginx/snippets/cms-https-listen.conf;  # 443 的开关，见下一节
}
```

六个决定，改这里之前要看懂：

1. **80 的 `default_server` 被本站接管，Debian 自带 default 站点已移走。**  
   以前 80 被主机防火墙挡着所以那个欢迎页一直不可达；一放开 80，它就会变成  
   「输入 IP 看到 Welcome to Debian + `Server: nginx/1.24.0 (Ubuntu)`」（全局 `server_tokens` 没关），  
   等于给扫描器报版本。本站块里有 `server_tokens off`，让本站兜住乱 Host 更干净。  
   原件挪到 `/root/cms-bak/sites-enabled-default.symlink`，一条 `mv` 回去即可恢复。  
   ⚠️ 同一端口留两个 `default_server`，`nginx -t` 会直接失败 → 部署脚本的自动回滚负责兜。
2. **`server_name` 只写域名，不写 `_` 通配。**  
   「乱 Host 落到哪」这件事交给明写的 `default_server`，不靠通配名与默认站的匹配顺序（隐式、易变）。  
   `www.ty0712.com` **目前还没有 DNS 记录**，写上只是给以后加记录留位。
3. **80 关不掉，因为它只剩一个用途就是续证书。**  
   ACME 的 http-01 是来 80 取文件的；换成 DNS-01 虽能彻底关 80，但要往服务器放一把能改 DNS 的
   长期 AccessKey —— 比留一个「只发挑战文本」的 80 危险得多。所以明文收口的现实边界是
   「80 上只有挑战文件与一条 302」，不是「80 不监听」。
4. **跳转用 302、且目标写死域名。**  
   101 的永久跳转会被浏览器缓存，证书一出问题就退不回明文（片段 301→302 已经踩过同样的坑）；  
   拿 `$host` 拼跳转目标等于让客户端决定把人送去哪（可做钓鱼跳转），所以写死 `ty0712.com`。
5. **`/gate/` 在明文侧是 404，不是 302。**  
   302 会把 token 原样写进没加密的 `Location`，等于在公网链路上广播唯一的登录凭据。
6. **`ufw` 放行 80 与 443，但**撤掉**了 8080**（`deploy-web.sh` 自己会做 `ufw delete allow 8080/tcp`）。  
   8080 收到回环后那条规则只是误导；阿里云**安全组**里的那条要自己去控制台撤，
   撤不撤都不影响 —— nginx 不在对外地址上监听，包进来也是连接被拒。

会话 cookie：不钉 `Domain`（下发在 [server/authd.py:972](file:///Users/wenweiqi/CLionProjects/Project/server/authd.py#L972)，
清除在 [server/authd.py:894](file:///Users/wenweiqi/CLionProjects/Project/server/authd.py#L894)，判据是
[server/authd.py:754](file:///Users/wenweiqi/CLionProjects/Project/server/authd.py#L754) 的 `_secure_suffix`），
`Secure` 则**按 scheme 条件加** —— nginx 在 `/__login`、`/__logout` 上用
`proxy_set_header X-Forwarded-Proto $scheme` 把「这次是不是加密」告诉 authd，authd 只在
看到 `https` 时把 `; Secure` 拼进去；**下发与清除用同一条判据**（属性对不上就删不掉 cookie，
而在明文请求里发 `Secure` 会被浏览器整条丢弃 → 回环那侧的登出静默失效）。
因为不钉 Domain，浏览器仍按「你刚才请求用的那个主机」存 cookie：域名与隧道里的
`127.0.0.1:8080` 各是一份会话，登两次是预期，不是 bug。

部署自测里钉的明文收口断言（`bash scripts/web/deploy-web.sh` 每次跑，`tools/test_gate_ui.py` 的
**T58 + T61** 钉脚本本身）：80 对 `/`、`/index.html`、`/style.css`、`/learn/` **必须 302 且
`Location` 恰是 `https://域名 + 原路径`**；明文侧 `/gate/<TOKEN>/` 必须 404 且**响应头里不许出现 token**；
8080 只许出现在 `127.0.0.1` / `[::1]` 上（用 `ss -ltn` 看真实监听地址，不看配置）；
443 下发的 cookie 必须带 `Secure`、回环那侧必须不带；HSTS 必须**只在 443 发出来**（值取 `max-age=15552000`），
明文那两侧 —— 80 的 302 与回环 8080 —— 必须**一行都不发**。

### HTTPS（443）：**已上线**（2026-10-20 裁决：**分两步**，第一步只上 443，80 与 8080 一字不变；
同日第二步已收口明文，见下面「第二步」与上一节）

`https://ty0712.com/` 现在打得开：Let's Encrypt EC-256 证书（`issuer = CN=YE1`，`notAfter = 2027-01-18`），
协商到 **TLSv1.3 + ALPN h2**，从本机不带 `-k` 验链 `Verify return code: 0 (ok)`。
第一步那天（当时登录后的落点还是 `/index.html`），443 上 `/`、`/index.html`、`/gate/<TOKEN>/` 的响应码与 80、`IP:8080` **逐条一致**
（`/learn/` 200、匿名一律 404）—— 收口之后 80 只会 302，部署自测改拿回环 `127.0.0.1:8080` 当基准。
签证书之前，443 只写在 `ufw` 里、没写进 nginx，外部打它是**毫秒级连接被拒**（内核回 RST）而不是超时（ufw 丢包）；
主块里那颗「开关片段」把这件事自动化了 —— 证书在才监听，不在就是空文件。

```nginx
# /etc/nginx/snippets/cms-https-listen.conf —— 由 deploy-web.sh 每次部署按证书在不在重新生成
listen 443 ssl http2;  listen [::]:443 ssl http2;
ssl_certificate /etc/nginx/ssl/ty0712.com.pem;   ssl_certificate_key /etc/nginx/ssl/ty0712.com.key;
ssl_protocols TLSv1.2 TLSv1.3;  ssl_session_cache shared:CMS_SSL:10m;  ssl_session_tickets off;
```

**为什么不把这几行直接写进主块**：那样证书一旦丢失或没签成，`nginx -t` 就因缺 cert/key 失败，
并把整站拖进自动回滚 —— 等于把「443 挂了」和「80/8080 还能用」绑成同一个故障。
现在证书不在，这个文件就是**空的**（注意：空文件也必须落盘，主块 `include` 了一个不存在的文件同样 `nginx -t` 失败）。
回退只要把它清空再 reload，443 消失、另两个入口毫发无伤。

**这三步已在 2026-10-20 全部跑过**（顺序不能乱，将来重装照抄）：

```bash
bash scripts/web/deploy-web.sh                    # ① 把 /.well-known/acme-challenge/ 放开
ACME_EMAIL='you@example.com' bash scripts/web/deploy-https.sh   # ② 装 acme.sh → staging 试签 → 正式签 → 装证书 + cron
bash scripts/web/deploy-web.sh                    # ③ 开关片段看到证书，这才写 443 监听并 reload
```

七条踩坑实录（都是 2026-10-20 当场实测的，别再推测。前四条决定「能不能签」，后三条是**真跑一遍才冒出来的**）：

1. **服务器上 `raw.githubusercontent.com` 被连接重置**、`cdn.jsdelivr.net` 也不通，但 `github.com` 可达（200 / 0.69s）
   → acme.sh 官网那句「curl 一把灌进 shell」在这里走不通，只能**钉 tag `v3.1.6` 的 git clone**（顺手把 commit 打进输出留证）。
   这跟本机有没有开代理无关：服务器上没有任何 proxy 环境变量。
2. **`/.well-known/acme-challenge/probe` 之前实测 404** —— 它落在 404 模型的受保护兜底里，行为没错，
   但 LE 正是以匿名访客身份来取这个文件的，所以**必须先开一条公开的 `^~` location** 才可能签成证书。
   `deploy-web.sh` 与 `deploy-https.sh` 都会在真签之前造一个一次性探针文件、要求拿到 200，拿不到就直接失败。
3. **线上 nginx 是 1.24**：独立的 `http2 on;` 指令是 1.25.1 才有的，写在 1.24 上 `nginx -t` 直接红
   → 只能 `listen 443 ssl http2;`。
4. **Let's Encrypt 对同一注册域名限 5 张证书 / 7 天** → 先打 staging（假证书、同一套 http-01 流程）验全链路，
   通了才动正式环境；`deploy-web.sh` 里**绝不出现签发命令**，重部署不该吃 CA 限额。
5. **`acme.sh --install` 必须先 `cd` 进源码目录再调**：它是按**当前目录**往 `--home` 拷
   `acme.sh` / `bin` / `dnsapi` 的，用绝对路径从别处调会得到
   `cp: cannot stat 'acme.sh'` + `Installation failed`，并且**留下一个空的 `/root/.acme.sh` 目录**
   （脚本因此要 `rm -rf` 再装，否则下一次「已存在」判断会被半个空壳骗过）。
6. **staging 签完必须把这条域名记录清掉，正式签才真的发生** —— 而且清它有两层坑：
   · 参数是 `--remove` 不是 `--delete`（v3.1.6 里没有 `--delete`，写错只得到 `Unknown parameter` + 退出码 1，
     假证书记录原地不动）；
   · `--remove` **只删配置、不删文件**，key/cert 仍留在 `/root/.acme.sh/<域名>_ecc/`，
     下一次 `--issue` 撞到已存在的域名私钥会回 `Domain key exists, do you want to overwrite it? … add --force`
     并失败 → 所以还得 `rm -rf` 那个目录。
   最阴的是：不清记录直接 `--issue`，acme.sh 回「Domains not changed. Skipping.」**而退出码仍是 0**，
   那张 `(STAGING) Baloney Bulgur` 假证书会一路装进 `/etc/nginx/ssl`，浏览器现场报「证书不受信任」。
   所以 `deploy-https.sh` 在装完证书当场 `grep STAGING` 验一次 issuer，是假证书就删掉并失败退出 ——
   `deploy-web.sh` 的开关片段只看**文件在不在**，它分辨不了真假证书。
7. **acme.sh v3.1.6 的默认 CA 已经不是 Let's Encrypt，而是 ZeroSSL**：正式签那行不写 `--server`
   就会静默签成 `issuer = ZeroSSL ECC DV SSL CA 2`（实测踩过一次）。两张证书浏览器都认，
   但本仓库的限额口径、账户邮箱、续期说明全按 LE 写，所以 **CA 必须钉死**
   （`--server https://acme-v02.api.letsencrypt.org/directory`），别跟着上游默认值漂。

账户邮箱只出现在服务器上的 `/root/.acme.sh/account.conf`（`--accountemail`），**不进 git、不进仓库**；
LE 用它发「到期 / 续期失败」通知。另外记着的：`www.ty0712.com` **没有 DNS 记录**，所以只签裸域名（http-01 签不了未解析的名字）；
证书用 EC-256；私钥只在服务器 `/etc/nginx/ssl/`（600 root），**不进 git、不进任何 rsync 源、不进备份快照**。
`--reloadcmd 'systemctl reload nginx'` 是续期链路的最后一步 —— 少了它，症状是「续期成功但线上仍用旧证书」，
平时毫无征兆，到期那天突然打不开；部署自测因此会报证书剩余天数，不足 21 天直接红字警告。

**第二步（2026-10-20 同日获批并已上线）**：① 80 除 ACME 挑战外一律 `return 302 https://…`
（刻意 302 不用 301：永久跳转被浏览器缓存，证书一出问题就退不回明文，与「片段用 302 不用 301」同一取向；
跳转目标写死域名，不拿客户端可控的 `$host` 拼）；② cookie **按 scheme 条件**加 `Secure`
（nginx 在 `/__login`、`/__logout` 上 `proxy_set_header X-Forwarded-Proto $scheme`，authd 见到 https 才加，
下发与清除共用同一条判据）；③ `IP:8080` 那个历史入口**收回服务器内部**（只绑 `127.0.0.1` / `[::1]`，
ufw 那条 8080 一并撤掉）—— 当时它还是"永远明文的对外入口"，是这一步唯一没被跳转覆盖的洞。
④ `Strict-Transport-Security` 于 **2026-10-21 单独点头后加上**（前面三步都不是它，因为它一旦发出去就退不回去）：
值取自 `map $scheme $cms_hsts`，https 给 `max-age=15552000`（180 天）、其余给空串 —— nginx 的 `add_header`
遇到空值**不发这一行**，所以明文 80 的 302 与回环 8080 都不带这个头（写死字面量就分不清「谁发的、到底生效没有」，
这正是最难查的那类歧义）。**取 180 天而不是 365**：443 是唯一的对外入口，证书一断就是全站打不开，
而这个头本身只能等过期或清浏览器状态，宁可锁得短一半；**不带 `includeSubDomains`/`preload`**：
现在只有裸域名有 DNS 记录，加上等于给以后所有子域预先上锁。
前提是先有探活第 7 项（证书剩余天数 <14 天发 `/fail`）—— 锁上之后只有那盏灯能提前把「快到期了」送到。

自己人怎么用那个收回环的口子（本机 Mac 上开，别忘 `-p <SSH端口>`）：

```bash
ssh -p <SSH端口> -L 18080:127.0.0.1:8080 root@<服务器IP>     # 挂着别关
# 然后本地浏览器开 http://127.0.0.1:18080/
```

留着它（而不是干脆删掉监听）有两个理由：探活第 4/6 项和部署自测整段都拿
`127.0.0.1:8080` 当「内容块活着 + 闸门语义对不对」的基准，删了就是误报一片；
以及 443 出问题时它是留在机器内部的检修口（去掉 `127.0.0.1:` 前缀即恢复对外）。
代价：别人手里旧的 `http://<IP>:8080/` 内测地址当场失效，要给人只能给 https 那条 + 秘密入口。

| 端口 | 只放行防火墙时 | 现在（证书已签） | 含义 |
| --- | --- | --- | --- |
| 443 | 44 ms 连接被拒（内核回 RST） | **TLSv1.3 + h2 握手成功**，LE 证书链可验 | 开关片段里写上了监听 |
| 80 | — | **302 到 https**（挑战文件除外） | 明文只负责送人，不再 serving 内容 |
| 8080 | — | 外部**连接被拒**（nginx 不在对外地址上听） | 已收回 `127.0.0.1`，要用得开 SSH 隧道 |
| 8443（对照组，没放行） | 超时 | 仍超时 | ufw 默认丢弃 |

域名侧的密码与 cookie 从此不再明文过网，`Secure` 也带上了。但**这道门仍不能叫安全边界**：
入口 token 走 URL（日志、浏览器历史都留得下）、口令是共享的、HSTS 只管见过 https 之后的人，
未登录者对外靠的还是 404「当作不存在」而不是 TLS。收口收的是「明文能被旁观」这一路，
不是把软隔离升级成认证。

| 浏览器被弹出，但只 push 过、没跑过 `revoke-all`                            | 那次 push 的表里可能夹带了 gen/rev 的变化                      | `ssh … "tail -3 /var/lib/cmsgate/usage.jsonl"` 看时间，比对 `ls -1t /var/lib/cmsgate/passwords.json.bak-*` 里各代的 gen |
| 有人反馈「密码不对」，但你 `list` 看它是启用的                                 | 可能是**已停用/已过期**，或他在试的其实是别的密码                       | `show <id>` 看这条的状态与**它自己的**访问记录；被停用/过期时提示是分开的                                                                  |
| `cms add --hours 6` 建出来的是「永久」，但**不报错**                          | 旧版本 bug：`cmd_add` 里判断"给没给有效期"的代码漏了 `--hours`   | 已修（2026-10-17）。现在「哪些参数算有效期」由 `expiry_given()` 统一判定；`cms list` 看到 `永久` 就是真永久                      |
| 提示「这个密码已被停用 / 已过期」                                            | 正常的状态校验（不是故障）                                     | `enable <id>` / `expire <id> --never`，然后 `push`                                                               |
| 忘了管理口令（想切总开关进不去）                                             | 管理口令只存哈希，无法找回                                     | `cms admin-init --force` 重设一条（需要能 ssh 到服务器，也就是本来就有最高权限）                                |
| 想临时免密开放（内测/维护）                                                | 用总开关                                              | `gate off`，用完 `gate on`；`gate status` 随时确认当前状态                                                              |
| **界面筛选面板里只有「（全部）」，其余列都点不出选项**                      | 改了 `gate_ui.py` 但**没重启**——页面资源读盘、Python 代码不读盘 | 顶栏会有红字「服务端代码已更新」；Ctrl-C 后重跑 `cmsui`                                                                 |
| 界面顶栏显示「服务端代码已更新 / 重启 cmsui 生效」                            | 同上，这是提醒不是在报错                                     | 重启进程即可                                                                                                  |

### ⚠️ 最容易把自己锁在门外的操作

1. **推送空表**——工具默认拒绝，别加 `--force`。
2. **删掉唯一一条密码**——删之前先 `add` 一条新的。
3. **`passwords.json` 变成非法 JSON**——push 有预校验，别手工编辑服务器上那份。
4. **`secret.key` / `passwords.json` 属主或权限写错**——服务读不到就全员 401。  
   正确是 `cmsgate:cmsgate` + `0600`。
5. **反着来：先跑 `deploy-web.sh` 再跑 `deploy-gate.sh`**——nginx 一重载就要求
   `auth_request`，后端还不在，谁都进不去。正确顺序永远是 **gate → web**。
   改了 `authd.py`（例如新增 `/entry`）时尤其如此：旧 authd 没有这个端点，
   秘密入口那条 `proxy_pass` 会拿到 404，部署自测当场就会报出来并提示先跑 `deploy-gate.sh`。
6. **`gate off` 之后忘了 `gate on`**——那一刻是**任何人点开网址就能玩**；不是"锁在门外"，
   但方向更糟。`gate status` 一行就能确认，顺手养成习惯。

## 存活监控与数据备份

> 这一节是 2026-10-18 上线的两套「出事能知道、丢了能找回」的机制。
> 都只在**服务器**和**你自己的 Mac** 上跑，不引入任何新的对外服务。

### 存活监控：Healthchecks「死人开关」

思路是**反过来的**——不是"坏了才报警"，而是"**没按时报平安就报警**"。
服务器每 2 分钟向 Healthchecks.io 发一个成功 ping；一旦**连 ping 都发不出来**
（整机宕机 / 网络断 / 定时器死），Healthchecks 在 Period(2min)+Grace(5min) 后
**主动发邮件**告警。这样连"探活脚本自己挂了"都能被发现。告警邮箱：`<你的告警邮箱>`（邮箱地址不写进文档——它在第三方监控服务的收件箱里，等于公开）。

每轮 ping 之前，`server/cmsgate-healthcheck.sh` 先跑**十三项探活**（服务器版十四项；
八项→九项→十三项：2026-10-31 起第 9 项是 cmsdist 跑分调度，2026-11-02 补上第 10–13 项
= sshd / fail2ban+chrony / 内存与 swap / 公开学习站；
第 14 项是 QQbot——**bot 段在服务器专属的 `/opt/cmsgate/healthcheck-extra.sh` 里，
不进仓库**，QQbot 相关改动不进 git），
任一项失败先记一笔连续失败计数，**连续 2 轮仍失败才发 `/fail`**（同样触发邮件，
≤4 分钟；单次抖动不告警——2026-11-06 astrbot 探测一次瞬时 000 误报 DOWN 后加的去重，
计数在 `/opt/cmsgate/healthcheck-fails`，全绿自动清零；真宕机仍由下面的死人开关兜底）：

| # | 探活 | 抓的是什么故障 |
| --- | --- | --- |
| 1 | `systemctl is-active cmsgate` | 鉴权服务没在跑 |
| 2 | `curl 127.0.0.1:8090/health` | 进程在但**卡死**（systemd 看不出来） |
| 3 | `systemctl is-active nginx` | nginx 没在跑 |
| 4 | `127.0.0.1:8080/dist/main.js` 必须 **404** | **200=闸门被绕过**；401=配置回退成「承认存在」（应走 `=404 /__nf`）；502/504=authd 经 nginx 不可达 |
| 5 | `df` 用量 < 90%（`/` 与 `/var/lib/cmsgate`） | **盘满**：进程都活着但写盘失败 → 登录异常/日志丢，前四项看不到的静默故障 |
| 6 | 秘密登录入口必须 **200 且正文含 `gate-form`** | 入口本身打不开：片段被误删 / reload 坏了 / `gate` 目录权限变了。★ 只有这一项看得见 —— 前五项会全绿，而唯一症状是「访客说链接打不开」 |
| 7 | 证书剩余天数 ≥ 14（`openssl x509 -enddate` 读 `/etc/nginx/ssl/ty0712.com.pem`） | **续期静默失败**：acme.sh 的 cron 没跑 / 80 被临时挡 / 撞上签发限流。到期之前线上毫无症状、前六项全绿；到期当天 80 把所有人 302 到 443 → **整站打不开**，这是唯一提前的灯 |
| 8 | `/root/cms-backup` 里最新 `cms-*.tar.gz` 的 mtime 距今 < 26 小时 | **每日快照停了**：crontab 被覆盖 / 磁盘配额满 / tar 报错，全都只写 journal、外面毫无症状。等到真要恢复时才发现最新快照停在一个月前。26h = 错过一次 03:17 就报，又不会被 03:17→24:00 的正常间隔误伤 |
| 9 | `curl 127.0.0.1:7120/ping` 返回 ok（2026-10-31 起） | **cmsdist 跑分调度挂了**：与闸门完全独立，坏了不影响登录，但唯一症状是客户端领不到任务、跑分静默停摆 |
| 10 | `systemctl is-active ssh` | **sshd 挂了**。探活本身是出站 curl、不经过 sshd，所以它死了监控照样绿；而 ctlui 看板（ssh 跑 `admin-lite`）、所有 `deploy-*.sh`、Mac 那条备份 rsync 全废，跑分客户端却一切正常 —— 唯一症状是「我连不上服务器」 |
| 11 | `fail2ban` 在跑 + `chronyc tracking` 的 \|offset\| < 2s | **爆破无人挡**（闸门密码表就在 `/var/lib/cmsgate`，被猜中直接登进游戏）；**时间漂移**（lease 回收、任务冷却、快照新鲜度 <26h 三处判断会集体失真，而每一项单看都"正常"） |
| 12 | `free`：可用内存 > 15%、swap 占用 < 60% | **活着但慢死**。第 5 项只盯磁盘，看不到内存压力；2G 机器上 OOM 前的疯狂 swap 会让所有服务变哑。下限 2026-11-03 从 8% 抬到 15%（≈260 MB）：翻 7 天 sysstat，真·available 每天最低 454~649 MB、used 峰值最高 1008 MB，15% 还在最差实测值下面一档，不会半夜误报；原来的 8%（≈139 MB）等于只剩最后一格才吭声。swap 上限 60% 不动（现值 9%） |
| 13 | `127.0.0.1:8080/learn/` 必须 **200 且标题含「C++ 数据结构与算法图解」** | **公开学习站静默 404**。第 4 项只测受保护资源的 404 口径，答不出「公开页还在吗」；`/learn/` 不需要登录，挂了没人反馈。标题标记是**故意的耦合**：宁可改版时误报，也不让「200 但内容是兜底页」蒙过去 |
| 14 | QQbot 容器在跑 + bot 配置/NTQQ 快照新鲜度（2026-10-28 起，只在服务器扩展文件） | **QQbot 悄悄挂了**：容器退出或快照停更，聊天机器人失联，而其余十三项全绿——QQbot 不进仓库，常规探活看不到它 |

> 第 4 项故意打**受保护**的 `/dist/main.js` 而不是登录入口：它只验证「闸门还在挡」，
> 不依赖任何具体 URL。所以 `cms gate-path rotate` 换登录入口**不会影响这一项**。
> 第 6 项相反，它**必须**知道 token —— 从片段首行 `sed` 出来，**只在本机读**。
> 第 7 项读的是**本地 PEM 里的到期日**，不是「现在 TLS 好不好用」：证书一旦被删或装歪，
> `nginx -t` 会失败、reload 不生效，而第 3 项仍报 nginx 正常。阈值 14 天是因为 acme.sh
> 的提前量本来就 30 天 —— 健康系统不会低于 ~30，掉到 14 以下说明已错过两轮以上重试。
>
> ★ 两条硬约束（改这个脚本前先读）：
> ① 失败原因串里**绝不带 token**，因为 `ping_fail` 的文本会经 `/fail` **发给第三方监控服务**；
> 取不到 token 就报「无法确认登录入口」，绝不把拿到的值拼进消息。
> ② 脚本里不许出现 `https://` 字面量（`deploy-monitor.sh` 的自测会 grep 它并判红）。

**ping URL 是密钥**（拿到它的人能伪造"一切正常"、也能刷 `/fail` 骚扰你）：
只存在服务器 `/etc/cmsgate/healthcheck.url`（`600 root`），由 `deploy-monitor.sh`
经 stdin 注入，**绝不进 git、绝不进 argv**。2026-10-25 复审后，探活脚本内两处
成功/失败 ping 的 URL 也不再拼进 curl 的命令行 —— 与 gate token 同一套
`printf 'url = …' | curl -K -` 模式经 stdin 交给 curl（`/proc/<pid>/cmdline`
本机所有账户可读，argv 会泄；printf 是 shell 内建、不进进程表）。
上线时做过负向测试（`systemctl stop cmsgate` → 约 91 秒后收到告警邮件）。

> ★ 2026-11-02 补盲那天又做了一条真负向（把第 12 项的内存阈值临时收紧到不可能满足），
> 结果**探活自己报了 FAIL、`/fail` 也发出去了，部署脚本却照样打勾**：`ping_fail` 按设计
> `exit 0`（已告警就不必再让 systemd 记一次 failed），而自测既看退出码、又拿
> `journalctl -n 20` 的历史去 grep `OK:` —— 上一轮的绿字足以把这一轮的红字盖过去。
> 现在自测把窗口收到本次触发之后（`--since` 本轮起点）再 grep `^OK:`，退出码只用来认
> 「脚本自己没跑起来」那一类。这和 `/fail` 走错通道是同一族谎：**告警链路的每一环都要用
> 一条真负向验，形状检查验不出方向反了**。

```bash
./scripts/web/deploy-monitor.sh          # 部署/更新探活脚本与 timer（服务器上已有 ping URL 就沿用，首次或换 URL 才喂）
ssh -p <SSH端口> root@<服务器IP> "systemctl list-timers cmsgate-healthcheck.timer"
ssh -p <SSH端口> root@<服务器IP> "journalctl -t cmsgate-healthcheck -n 20 --no-pager"
```

### 数据备份：两层

`/var/lib/cmsgate`（密码表 `passwords.json`、签名密钥 `secret.key`、配置 `gateconfig.json`、
访问日志 `usage.jsonl`、登出吊销表 `revoked.json`、背景图 `webbg*`）是**唯一的真相源**，误删/误覆盖/重装系统/实例释放
都会全丢。快照**另外还收一份** `/etc/nginx/snippets/cms-gate-path.conf`（秘密登录入口）。两层备份：

| 层 | 触发 | 动作 | 位置 | 保留 |
| --- | --- | --- | --- | --- |
| 服务器本地 | 每天 **03:17**（systemd timer） | `tar` 打包 | `/root/cms-backup/`（`600 root`） | 最近 **28** 份 |
| Mac 异地 | 每小时 + 每次登录（LaunchAgent，`StartInterval` 而非固定时刻 —— 合盖过夜不会漏） | `rsync` 拉取（无 `--delete`） | `~/Backups/cms/`（`600`） | 最近 **1000** 份 |

> 2026-10-28 起，同一 timer 另打 **QQbot 两路快照**：`bot-cfg`（每日，留 28 份）、`bot-ntqq`（周三/周日，留 8 份），
> Mac 层照常拉取；`bot-cfg` 打包时 `--exclude data/temp data/backups`（媒体缓存只进不清，会把快照撑到 300M+）。
> 2026-11-02 起这两路连同**媒体缓存按龄清理**（`data/temp` 里满 7 天的 `media_image_*`）一起写进仓库副本
> `server/cmsgate-backup.sh`，与服务器 `/opt/cmsgate/backup.sh` **逐字节一致**——此前它只存在于服务器，
> 而 `deploy-backup.sh` 是整文件覆盖，谁跑一次部署就会把它们静默抹掉。
> ⚠ 仍然只在服务器上的是**探活脚本的 QQbot 段（第 10 项）**，见下表与 `deploy-monitor.sh` 的提醒。

Mac 那层是**真异地**：复用现有 SSH 信任、**只出站**，不新增任何对外监听。
单份约 575 KB，1000 份满额约 575 MB。

**为什么把 nginx 片段也打进快照**（2026-10-19 加）：片段里那个 token 丢了，**任何人都再也登不进来**
——访客手里的网址全线 404，`cms gate-path status` 也没得读，只能 `rotate` 发一条新入口再挨个通知。
这是纯粹的可用性缺口，而**信任域一点没扩大**：同一批快照里本来就有 `secret.key`
（拿到它就能伪造会话 cookie）和整张密码表，多一个 nginx 片段并不改变"这批文件必须当成密钥看待"的性质。
所以 `backup.sh` 的打包逻辑是**两支**：片段存在就一起打，不存在（全新机器还没部署 nginx）就维持原样，
否则 `set -eu` 会在第一次备份时把整个备份打死。

⚠️ 解包时的一个物理后果：片段的 tar 成员名是 `cms-gate-path.conf`（不带目录），
整包解到 `/var/lib/cmsgate` 时它会落到**数据目录**里而不是 `/etc/nginx/snippets/`，需要手动搬一次 —— 
[`server/RESTORE.md`](../server/RESTORE.md) 的「登录入口片段」一节给了直接解到正确位置的命令。

**快照里含 secrets**（密码表 + 签名密钥 + 明文 IP 日志 + **登录入口 token**），所以：

- 服务器与 Mac 两侧都是 `600`，备份目录都在**仓库外**（`/root/cms-backup`、`~/Backups/cms`），
  **绝不进 git、绝不上传第三方**。
- **不做落盘加密**（刻意取舍）：传输已由 SSH 加密，静态存储靠 `600` + 自有设备，
  与既有裁决（日志存明文 IP、管理口令不轮换）敏感度一致；避免"备份有了、解密的钥匙丢了"。

```bash
./scripts/web/deploy-backup.sh           # 部署服务器层（含恢复演练自测）
./scripts/web/install-mac-backup.sh      # 在 Mac 上跑一次，装 LaunchAgent

bash tools/mac-backup-pull.sh        # 手动立刻拉一份到 Mac（不等下一次自动拉取）
ssh -p <SSH端口> root@<服务器IP> "systemctl start cmsgate-backup.service"   # 手动立刻打一份服务器快照
```

**到点 Mac 没开机怎么办**：LaunchAgent 用 `StartInterval 3600` + `RunAtLoad true`，不是固定时刻——
「每小时一次、登录/加载后立刻再来一次」，所以合盖过夜不会漏整段（醒来后第一个整点补上），
关机也不会在某一天留下永久空洞。真实缺口仍然是：服务器只留 28 份，
若 Mac 连续关机 > 28 天，中间几天的快照会在服务器端被轮转删掉，Mac 永远拉不到那几天
（但下次开机仍会拉到最新的）。

**Mac 拉取自己有一条死人开关**（2026-11-02 加）。服务器探活的第 8 项只看
`/root/cms-backup` 里快照新不新 —— 快照打成功、但 Mac 这份**没拉走**（密钥失效 /
本地盘满 / 远端目录被清）时，异地那份已经断供而监控全绿，属于「备份看起来有、实际没有」。
所以 `tools/mac-backup-pull.sh` 拉取成功后发一条成功 ping、非 0 退出发 `/fail`。
这条 check 单独建，**Period 7 天 / Grace 1 天**：合盖过夜是常态，不能一合盖就报红，
所以它报的是「异地那份落后一周了」而不是「备份没了」。Ping URL 是密钥，只存
`~/.cmsgate/mac-pull.url`（600，仓库外），由 `install-mac-backup.sh` 交互注入，
绝不进 git / argv；URL 文件不存在时只打一行提示、**不让备份停摆**。

> ★ 首跑就抓到一个只有真跑才能发现的 bug：EXIT trap 里那句原本写成 `'... '"$rc"' ...'`，
> `$rc` **在定义 trap 的那一刻**就跳出单引号被展开，`set -u` 下报 unbound variable，
> 脚本连 rsync 都没跑到就退 1 —— 而 `bash -n` 与全部字符串断言都是绿的（T70 那批形状检查
> 全都放过了它）。正确写法是整条留在单引号里、变量写成 `${rc}`（全角括号紧跟 `$rc`
> 在本机 zh_CN.UTF-8 的 bash 3.2 下会被并进变量名）。现在 T70 里有三条**把脚本真跑一遍**的
> 守卫：假 HOME + stub 的 rsync/curl，验「成功→退 0 且发基址 ping」「rsync 挂→非 0 且发 `/fail`
> 且原因串带退出码」「curl 自己坏了→退出码仍为 0」「没有 URL 文件→不发 ping、备份照跑」。

**恢复**：见 [`server/RESTORE.md`](../server/RESTORE.md)——含"恢复会影响什么"、
服务器本地回滚（场景 A）、只恢复密码表+密钥、以及从 Mac 拉到全新服务器（场景 B）的完整步骤。

## 默认页开关：游戏 ⇄ 学习站（`cms landing`）

**为什么有这个东西**：监管要求站点根路径对外是 C++ 学习内容而不是游戏。
做法不是藏游戏，而是把**真实的学习站**（`/learn/`，16 篇图文+代码+SVG）公开放出去，
游戏继续留在闸门后；根路径归谁，由这一个开关决定。

| 模式 | `/` | `/learn/` 与其他路径 | 游戏在哪 |
|---|---|---|---|
| `game`（开放站，默认） | `302` 到 `/game` | `/learn/` **仍公开**（学习站直达，2026-10-22 裁决保留）；其余未定义路径 `302` 到 `/game` | `/game`（未登录 **404**） |
| `learn`（学习站） | `302` 到 `/learn/` | 除 `/game` 外一律 **404** | `/game`（未登录 **404**） |

**游戏只有一条地址：`/game`**（`/game/` 会 302 补掉尾斜杠）。两种模式下它都由
`auth_request` 守着：带有效会话放行，没有就 `404 /__nf`——不吐 401、不吐密码页，
对一个不知道入口的人来说这里什么都不存在。登录后的落点也是 `/game`，所以
“会话有效却进不了游戏”这种模式相关的死路不会再有。

**秘密入口 `/gate/<TOKEN>/` 会看会话**：已认证直接 302 到 `/game`（authd 的
`GET /entry`），未认证才给密码页。学习站模式下对外唯一的入口是 `/`（公开学习站）；
开放站模式下 `/` 虽然直达 `/game`，但**没会话的人看到的仍是 404**，密码仍然要过，
只是不用再记那条秘密网址。

```bash
cms landing status          # 只读，不问管理口令
cms landing learn           # 切到学习站（要管理口令）
cms landing game            # 切回游戏（要管理口令）
```

cmsui 顶栏也有一枚「默认页」芯片，点它走同一套 CLI（口令照旧弹窗输入）。

**实现要点**（改任何一环前先读 `tools/test_gate_ui.py` 的 T50，契约都钉在那）：

- 模式存在服务器上的 `/etc/nginx/snippets/cms-landing-root.conf`，**首行是标记**
  `# landing-mode: game|learn`。站点配置里没有 `location /`——根路径与兜底规则都
  由这一份片段带进来（主配置再写一个 `location /` 就是重复定义，nginx 直接起不来）。
- 切换流程：备份现片段 → 写 `.new` 再 `mv` → `nginx -t` → `reload`；
  任一步失败自动把备份还原并再验一次，**不会留下起不来的 nginx**。
- `deploy-web.sh` **保留运维当前模式、但重渲染片段正文**：旧片段可能缺 `/game`
  这条新规则，不重渲染就会出现「登录成功 → 落点 404」。读不出首行标记时按 `game` 写并警告。
- “已认证直达 `/game`”不能写成 `if` / `return`：那在 rewrite 阶段跑，比 `auth_request`
  还早。所以守卫路径的 `proxy_pass http://127.0.0.1:8090/entry` 放在 content 阶段
  ——authd 的 `/entry` 验完 cookie 再 302 `/game`；未认证时 `error_page 401 … = /gate/<TOKEN>/index.html`
  把密码页顶上来，密码页与 css/js 都在同一 `^~` 前缀里（不走 auth_request）。
- `/learn/` 用 `location ^~ /learn/` 公开：只有 `^~` 能压过带 `auth_request` 的
  `~* \.(js|css|...)$` 正则，否则 `/learn/app.js` 会 404。它的 `try_files`
  **绝不**回退 `/index.html`——那会把受保护的游戏 HTML 从公开路径漏出去。
- 登录后的落点统一是 `/game`（`web/gate/gate.js` 与服务端 303 同口径）：两种模式下
  它都是唯一的游戏地址，不会因为模式不同而落空。
- 会话沿用 cookie 的 24 小时上限，不加空闲超时：关掉浏览器（会话 cookie 不持久化）
  即失效，开着浏览器最多 24 小时。
- 学习站本身**不链接游戏、不提背景图**，搜索框只搜学习文章——没有任何隐藏入口。

## 访问日志与隐私

`usage.jsonl` 每次登录（成功/失败）追加一行，字段：

| 字段 | 内容 |
| --- | --- |
| `ts` | UTC 时间（`YYYY-MM-DDTHH:MM:SSZ`） |
| `event` | 事件类型（目前恒为 `login`，为将来其它事件预留） |
| `ok` / `reason` | 是否成功 / 失败原因（`bad_password`、`throttled`、`disabled`、`expired`） |
| `pwid` / `label` | 哪条密码（失败且没匹配到任何条目时为空） |
| **`ip`** | **明文 IP**（要让管理员回答"这条密码是谁在用、从哪来的"） |
| `ip_hash` | 同一 IP 的 HMAC 哈希（旧记录只有它；分享日志时可以只给这个） |
| `ua` / `ua_family` / `browser` / `os` / `device` | 原始 UA（截断 300 字）+ 解析出的浏览器/系统/设备 |

**闸门开放（免密）时也登记**：`require_password=false` 期间访客不输密码，
`/auth` 放行时写一条 `ok=true, reason="gate_open", pwid=null` 的记录（管理界面
结果列显示「免密放行」）。因为 nginx auth_request 对页面和每个资源都会打一次
`/auth`，按 (ip_hash, UA) 做了 **5 分钟去重窗口**——同一访客窗口内只记一条，
所以条数是「访客数」量级而不是「请求数」量级；重启 authd 会重置窗口（多记，
不会漏记）。**这个窗口只作用于免密放行记录**：带密码的登录（成功/失败）每次
都如实记账，不去重。

**⚠️ 这是明文 IP，比之前（只存哈希）更敏感**，所以：

- 文件权限 `0600`、属主 `cmsgate`，目录 `0700`；**只有 root 与 `cmsgate` 能读**。
- 对外分享/贴日志前，把 `ip` 与 `ua` 字段删掉、只留 `ip_hash` 与「浏览器 / 系统」——
  这两样足够定位问题，又不泄露具体访客身份。工具侧 `usage` 默认只显示 IP 与解析结果，
  原始 UA 要加 `--ua` 才打印。
- 单文件到 5 MB 会轮转成 `usage.jsonl.1`（**只留一代**）。想长期留存就自己配 logrotate；
  目前靠"只留一代"控制体积，别让它无限长。
- 换 `secret.key` 之后，历史记录里的 `ip_hash` 无法再与新记录关联（明文 `ip` 不受影响）。

## 已知限制

- **证书挂了 = 全站对外打不开**：443 是唯一的对外入口，80 只回一条 302，所以 Let's Encrypt
  那张证书到期没续上时，访客看到的不是降级明文、是错误页。探活第 7 项（剩 `< 14` 天发 `/fail`）
  就是为这条准备的。HSTS 已开（180 天，见「HTTPS」一节④），所以证书断了之后连「等浏览器重算明文」这条
  退路都没有 —— 这也是把 `max-age` 砍到一半、而不是照抄一年那个惯例值的理由。
- **单 IP 节流可被多 IP 绕过**——分布式撞库挡不住，那要靠云厂商的 DDoS 层。
- **使用记录（`usage.jsonl`）线上单文件超过 5 MB 会轮转成 `usage.jsonl.1`（只留一代）**，
  但每天 03:17 的快照会把它整份打包进备份（服务器留 28 份、Mac 留 1000 份），
  所以历史不会因轮转而彻底消失。**代价是 RPO ≤ ~24 小时**：两次快照之间新产生的日志，
  若期间服务器磁盘损坏则最多丢一天。要更小的 RPO 就调高快照频率（改 `cmsgate-backup.timer`）。
- **访问日志存明文 IP**（见上一节），这是功能需求与隐私的取舍；要更隐蔽就把 `ip` 换成再哈希。
- **背景图那两个文件 `no-store`**：版权未授权期间，「撤下要立刻彻底生效」优先于省流量，
  所以每次打开密码页都会重传 ~136 KB。拿到授权后可以改回长缓存。
- **`deploy-web.sh` 会用本地 `web/assets/bg.*` 覆盖线上背景图**。推了新图必须把本机
  那两张也换成同一张，否则下一次部署会把新图无声推回旧的（部署脚本本身不报错）。
- **开着 VPN 时，`cmsui` 可能不只本机能连**。2026-10-17 实测：服务自报绑定
  `127.0.0.1`（绑定完全正确），但从 utun 隧道的 `198.18.0.1` **也能连上** ——
  那是 VPN 客户端在做端口转发，与本服务无关。**经同一个 VPN 的其他人理论上能访问**。
  不用 VPN、或在 VPN 里关掉本地端口转发即可恢复。
  回归测试里这条标成 SKIP 并写明原因（绑定那条另有一条直接断言）。
- **`gate_ui.py` 不热加载**：改了它必须重启 `cmsui` 进程；前端资源则每次请求读盘、
  刷浏览器即可。这个不对称曾经导致「时间列能筛、其他列全空」，页面现在会自己提示。
- **`cms` 的远端参数管得很宽，为什么**（2026-10-21 修，★2）：`--server`、`--remote-dir`、
  `--web-root` 这三个值会被拼进十几条 `ssh`/`scp` 命令串里，全部在服务器上以 **root** 执行。
  攻击场景不是「黑客能改你的命令行参数」——是**操作者自己**：`cms webbg push --image`
  指向一个从聊天工具/网盘转存来的文件名，这类名字里出现单引号非常平常（`宝贝'$(id)'.webp`）。
  旧写法 `printf '%s' '<状态 JSON>'` 把带引号的路径原样插进单引号里，引号提前闭合，
  后半段变成一条独立命令在服务器上执行，而工具照常打印「✓ 已推送」——**成功了，所以你永远不会知道**。
  现在两道处理：① `_webbg_put_state` 里唯一那处「数据进命令串」的写入点改用 `shlex.quote`；
  ② 其余十几处逐条记得 quote 是迟早会漏的设计，所以在 `parse_args` 之后、任何执行之前
  加一道字符集关卡（主机只允许 `A-Za-z0-9._:@/-`，路径只允许 `A-Za-z0-9._/-`，都不许有空格，
  也不许以 `-` 开头——`--server=-oProxyCommand=…` 是喂给 ssh 自己的选项、在**本机**执行），
  不合规矩直接拒、**走不到 ssh**。`cms` 和 `cmsui` 两个入口都调它（cmsui 自己有一条
  `cd '<web_root>' && head -c …` 的背景图预览，不经过 gate_manager 的 `main()`）。回归里 T63 不是 grep 它长什么样，而是拿一个带单引号的
  真实文件名去写状态、再把生成的命令串用 `shlex.split` 还原一遍：payload 能作为一个完整
  token 原样回来才算通过。
