## ✅ B1/B2 已完成（2026-10-16 下午）

- [x] **B1.** `createdAt` 统一为 **UTC**，两端格式逐字节相同：`YYYY-MM-DD HH:MM:SS UTC`
  - 桌面端 `nowText()` 由 `localtime_r` 改为 `gmtime_r`（Windows 走 `gmtime_s`）
  - 网页端 `toISOString()` 本来就是 UTC，末尾补上 ` UTC` 标记
  - **为什么显式带 " UTC" 后缀**：这一栏仅供人阅读，只写 `05:17:12` 会让东八区用户
    当成自己的本地时间（差 8 小时），是最难发现的错法
  - 待办原文说「桌面 currentSeed() 不设该字段」——这句**已过时**，`main.cpp:107` 早已设了，
    真正的问题只是时区不一致
  - 测试里有一条专门断言「createdAt 确实是 UTC 而非本地时间」（与当前 UTC 相差 < 10 分钟）
- [x] **B2.** 两端 RNG 统一，且**顺带修掉了 C++ 端自己的跨平台不一致**
  - 起因比原判断严重：原来 C++ 用 `std::mt19937` + `std::shuffle` +
    `std::uniform_int_distribution` + `std::bernoulli_distribution`，
    而这后三者**全是实现定义**的（libc++ / libstdc++ / MSVC 各一套）。
    即**同一颗种子在 macOS 与 Linux 上就已是不同雷局**，存档跨平台早就废了。
    所以「让网页抄 C++」这条路根本走不通，必须两端一起换成自写的确定性算法。
  - 新实现 `src/core/Rng.h` ↔ `web/ts/rng.ts`：SplitMix32 扩状态 → **xoshiro128\*\***
    → 拒绝采样取有界整数 → Fisher–Yates **从后往前**洗牌。
    全 32 位运算，故 JS 侧用 `Math.imul` + `>>> 0` 精确复现，不需要 BigInt。
  - 回归闸门：`build/rngparity`（C++）与 `web/test/rng-parity.mjs`（TS）逐字节对拍 10 个用例，
    覆盖随机分型 / 手动分型 / 首点靠角靠边 / 雷数近上限 / 种子 0 与 0xFFFFFFFF 边界。**17 项全绿**。
  - 该测试**已验证真能抓错**：故意把 C++ 洗牌方向改成从前往后 → 10 例全报警并定位到方向；
    改回后恢复全绿。
  - 设计细节见 `docs/项目结构说明.md` §5.12

做排行榜时这正好是想要的（新记录必须用新算法重放），但**你以前存的「同一局」已经不再能复现**。
