──────────────────────────────────────────────────────────────────────────
C1：DP 阶梯重试（自适应上限）
──────────────────────────────────────────────────────────────────────────

机制：BucketDP::run 增加失败原因回传（1 宽度超限 / 2 工作量超限 / 3 其他），
  tryDp 改阶梯重试——宽度 8→9→10（buildOrder 是 O(n²) 便宜失败），
  工作量超限重试一次（kDpWorkCap 8M → 16M 表项）。
  ★ 内存守卫：msgs_ 保存全部 n 条消息，总内存 = work_×16B；计划原定 ×4 = 512MB
    太危险，按守卫优先收到 ×2 ≈ 256MB，正好覆盖实测失败模式（nv≈90、宽 7-8）。
  结构性失败（原因 3）不重试；同参重试仍然禁止（P2 的教训，纯函数白烧）。

统计口径：SolverStats 新增 dpWidthRetry / dpWorkRetry；tools/solver.cpp 新增
  「单局最坏 X.Xs（第 g 局）」。

实测（Hard 100 局 × seed=20261008，仅 C1，对照 P2 基线 14.0%/降级19/均时2.90s/最坏21.9s）：
  胜率 14.0% / 降级 19 / 单局最坏 21.9s（第 73 局）—— 与基线逐项一致；
  ★ 阶梯重试 0 次：19 个降级分量的 DP 放弃**全部**是结构性原因（failKind≥3），
    宽度/工作量上限根本不是瓶颈 —— C1 的原始假设（长尾是 8M 表项撞墙）被实测否定。
    阶梯机制保留（ harmless，未来参数变化时仍有价值），诊断编号已埋（见下）。
  增加失败原因分布统计（dpFailKind[8]）：1=宽度超限 / 2=工作量超限 / 3=fillScope 不变量 /
    4=target 序 / 5=root 非标量 / 6=空根 / 7=无变量线索不相容。

  ★ 诊断事故（必须记取）：第一版 dpFailKind 全是 0 桶（20 次），当时误读成
    「全是 fillScope 不变量失败」——实际是 BucketDP::run 忘了把 lastFail_ 拷进
    failKind 出参，调用方永远收到 0、阶梯重试从未真正触发。修成包装器回传后重测。
    教训：**埋点先验证埋点本身会响**（跑一次已知会失败的用例），否则统计数据是
    拿想象填的。

C2：消元序择优（min-fill / min-degree / 最小 scope 三贪心取最小诱导宽度）
──────────────────────────────────────────────────────────────────────────

机制：buildOrder 并行跑三种贪心，取诱导宽度最小者（n≤~100，代价可忽略）。
实测：三贪心在三档全部难度上产出**逐字节相同**的消元序（min-fill 每步都不输给
  另外两个），结果与基线零差异 —— 无害空转，保留三贪心作保险（min-degree 在
  约束结构变化时有机会接管）。宽度分布无变化。
通过标准：宽度分布（compDPHist/诱导宽度桶）改善；同 C1 口径复跑无劣化。
回退：保留原单一 min-fill 分支。

  工作量档 101 次；DP 放弃原因 [2=工作量]=40、[3=fillScope]=1；降级分量 39

──────────────────────────────────────────────────────────────────────────
A1：分层 BucketDP（修 2.24× 边际高估）
──────────────────────────────────────────────────────────────────────────

机制：BucketDP::runLayered —— 消息从标量 long double 升级为「按 (nr,ni) profile
  分层」的权重表（每 code 一个 map<profile→long double>）。子消息相乘变成沿
  profile 轴的二维卷积；消元变量把 (Δ实雷数,Δ虚雷数)（个数口径，与 computeSupport
  的 dr/di 一致）折进 profile。前向消息含本桶 delta；后向 M 表不含（边际/类型/
  回传时再折 —— ±1 与 -1 同为 (1,0) 增量，折早了 profCellTypes 就分不出真型）。
  卷积不可逆，回传「排除第 j 个子消息」用 pre/suf 前后缀卷积，不做除法。
  根消息 = profSolCnt[profile]；每变量消元时顺带累出 profCellMine/profCellTypes
  （per-profile 真型，与枚举 FULL 完全同构）。profSolCnt/profCellMine 从 int
  拓宽到 long double（DP 解数可达 5^40）。
  门槛：复数口径、标量 run 已成功、诱导宽度 ≤8（stride 内存守卫 160k）、
  单 map ≤4096 点、分层工作量 ≤4M 乘加。任一超限 → 保持标量 DPSOLVED（只增不减）。
  开关：MS_LAYERED=1（缺省关）；oracle：MS_DP_ORACLE=1。
  A2 接入：分层成功的分量 o.status=FULL → 自动进 globalFilter 与 exactProbs
  （analyze 里 fullIdx/absorbProb 的既有分流零改动）。

oracle 三道闸（Medium 20 局 + Hard 100 局，seed 20261024）：
  闸 1 暴力对拍：949 个分量被 Enumerator（节点预算 ×64、无 rlim/ilim）暴力穷尽，
    逐 profile 对拍 profSolCnt / profCellMine / profCellTypes —— **0 不一致**
    （另 1245 个大 Z 分量走标量交叉：ΣprofSolCnt≈Z、Σ_p profCellMine≈mineCnt，
    相对误差 1e-9，亦 0 不一致）。
  闸 2 概率恒等式：Σ_FULL分量 pickProb + pIn×absorb ≡ Rtot+Itot（P3-B 的 2.24×
    正是这条被假权重破坏）。心跳确认真的在跑（第一版只打印违规、差点重蹈
    「埋点没响」的坑）—— 全部调用成功、approx 回退 0、违规 0。
  闸 3 校准表（Medium 100 局 --dbg，truth 口径）：猜格绝大多数落 <2% 桶（887 次、
    实际 0%），高桶样本小（>=35% 桶 16 次、实际 62.5% vs 预测 50%，n 小属噪声），
    无系统性偏移 —— 且闸 1/2 已是逐项精确证明，校准只是第三方旁证。
  契约自检：必开误爆 0、位置错标 0、跨轴错标 0（分层分量参与见证与标记后仍全绿）。

分层规模（MS_LAYERED）：Medium 211/219 分量升格（回退 8）、profile 点数最大 393；
  Hard 100 局 1983/2381 升格（回退 398）、点数最大 541；Hard 500 局 10926/12668
  升格（回退 1742）、点数最大 615。Easy 零 DP 分量，逐局与基线逐位一致（无回归）。

A2：接入 exactProbs 与跨分量排序 —— **判活，大幅正收益**
──────────────────────────────────────────────────────────────────────────

接入方式：分层成功的分量 o.status=FULL，自动进 globalFilter / exactProbs /
  见证循环（analyze 的 fullIdx/absorbProb 既有分流零改动）。收益来源不是排序
  微调，而是**信息增量**：DP 分量此前被关在全局 (Rtot,Itot) 耦合之外，现在
  全局卷积能对它们的格子证明「必安全 / 必雷（含真型）」，并把被 2.24× 污染的
  猜格排序修正回真实边际。

配对 A/B（seed=20261024，同棋盘同局序，McNemar 精确二项）：
  Medium 500：65.0% → **86.4%**（+21.4 点）；仅基线胜 0 / 仅分层胜 107，p≈1e-32
    陷阱猜 185→101；降级分量 36→5；中局猜 3045→3329
  Hard   500：17.4% → **58.0%**（+40.6 点）；仅基线胜 6 / 仅分层胜 209，p≈1e-40

  两档均无一局回退方向的显著证据；Easy 1000 逐位一致。

耗时（干净单跑）：Hard 100 局单局最坏 22.4s vs 基线 20.7s（+1.7s，长尾仍是
  工作量撞顶的巨型分量本身）；500 局并跑时测得的 34.1s 为并行污染，不作数。
  Medium 500 局单局最坏 **9.0s vs 基线 14.5s（反而更低）**——分层给出的必安全
  格让求解器少走了存在性搜索的弯路。整体均值 ≈2×（分层卷积 + exactProbs 扩容），
  两档最坏耗时均不构成问题。
  接受理由：3.3× 胜率换最坏耗时 Hard +1.7s / Medium −5.5s；P3-B 的教训正是
  「别拿假权重换胜率」，这次的胜率全部来自可证明的信息增量。

收口：MS_LAYERED 缺省翻**开**（MS_LAYERED=0 回旧路径）；默认开与 MS_LAYERED=1
  逐局逐位一致（Medium 100 局 diff 干净）；经典口径不经过分层代码，对照臂不受影响。

── oracle 三道闸（回答「这数据是不是编的」）────────────────────────────

  闸 1 暴力对拍：用另一套算法（DFS Enumerator，节点预算 ×64、无 rlim/ilim 剪枝）
    独立穷尽分量，逐 profile 对拍「每个 profile 的解数 / 每格含雷解数 / 每格雷型」。
    Medium 20 局 77 个 + Hard 100 局 872 个 = 949 个分量，**0 不一致**；
    另 1245 个解数超 2e7 的分量走标量交叉（两种数据结构互证），也 0 不一致。
  闸 2 概率恒等式：Σ_FULL分量 pickProb + pIn×absorb ≡ Rtot+Itot。
    含义：模型里每一颗雷必须落在「FULL 分量格 ∪ 吸收池」里，所以全部格子的
    含雷概率加总必须精确等于剩余雷数。P3-B 那次的 2.24× 就是这条恒等式被假
    权重破坏（加总=真实雷数的 2.24 倍）。本次全部调用 0 违规、approx 回退 0。
  闸 3 校准表（Medium 100 局 --dbg，真值口径）：
    桶:        <2%     2-5%    5-10%   10-20%  20-35%  >=35%
    次数:       887      46      28      35       5      16
    实际踩雷%:  0.0     0.0    10.7     5.7    20.0    62.5
    含义：预测 P 落在某桶的猜格，实际有多少比例真踩了雷。高桶样本小属噪声；
    无系统性偏移（闸 1/2 已是精确证明，此表是第三方旁证）。

── 理论存活上界（注意：不是真上界）────────────────────────────────────

  基线：Medium 59.4%、Hard 28.5%；分层版：Medium 79.0%、Hard 43.5%。
  含义与坑：exp(Σlog(1-P)/局数) = 「按每步猜的存活概率连乘」。它用的是**当时
  算出来的 P**——旧版 P 被 2.24× 污染，P 偏大 → (1-P) 偏小 → 上界被人为压低，
  这就是旧版「Hard 实际 17.4% 贴着 28.5%」假象的来源之一。它有幸存者偏差
  （早死的局只乘了少数因子），Medium 实测反超上界是常态。只当「概率有没有
  算错」的烟雾报警器用，不能当可提升空间读。

── 数据可信度小结 ────────────────────────────────────────────────────

  ① 引擎每做一个证明动作都对着真实棋盘验证并计数，错一次亮一次红灯
    （必开误爆/位置错标/跨轴错标）——三档几万次证明全 0。
  ② oracle 用完全独立的暴力枚举对拍，不是自己证自己。
  ③ 求解器完全确定性：同 seed 重跑必出同一串逐局胜负，可随时复核。
  ④ Easy（无 DP 分量）逐位一致——排除全局副作用；经典口径不经分层代码。
  保留项：以上是 seed=20261024 一个种子族；换种子绝对值会浮动（Hard 估
  45~60% 区间），但配对提升幅度不会消失。

第五代诊断（2026-10-30）：陷阱猜构成 + 第二种子确认

陷阱猜三分类（猜时最小含雷率 ≥0.2 的「死亡级」猜，按当时概率的精确度分桶）：
  exact = 全盘概率都来自精确模型 → 该局面在信息论意义上**无安全格**，真死局；
  pool  = exactProbs 成功但盘上还有非 FULL 分量（那些格用吸收池对称假设，
          可能漏掉可证明的安全格）→ 有优化空间；
  approx= 概率整体回退估计 → 最可能藏着漏证。

  局面            陷阱猜   真死局(exact)   池口径(pool)   概率回退(approx)
  Medium 分层版     101       100              1               0
  Hard   分层版     470       192            278               0

  读法：**Medium 已到天花板**（几乎每个陷阱猜都是真死局）；**Hard 还剩约
  一半的陷阱猜发生在有回退分量的局面** —— 这正是「宽 9~10 解锁分层」的
  量化依据。注意 pool ≠ 全部可救：精确化之后其中一部分仍会是死局。

第二种子确认（seed=20261111，n=500，同棋盘逐局配对 McNemar）：
  Medium：63.8% → **87.0%**（仅基线胜 1 / 仅分层胜 117，p≈1e-33）
  Hard：  16.6% → **56.6%**（仅基线胜 5 / 仅分层胜 205，p≈1e-40）
